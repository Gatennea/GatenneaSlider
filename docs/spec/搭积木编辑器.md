# 搭积木编辑器（自由板型）

`模型文件_2026-10-24.md` §一 写的「最终让玩家在游戏内用已有滑块拼装配置、保存成模型
文件」由本文收口：**玩家不再手写 JSON**，进 GUI 摆积木即可，保存动作在幕后合成同一份
schema（那份 schema 见 `模型文件_2026-10-24.md` §二）。

> **入口（2026-10-25 迁移后的现行路径，详见 §5）**：右下角「模式」开关 → **创造** →
> **② 还原状态设计** → **搭积木（自由板型）**。谜题菜单里的「＋ 搭建新模型...」已删除。

---

## 1 三段分工

| 层 | 文件 | 职责 |
|---|---|---|
| 纯逻辑（零 pygame，可单测） | `engine/editor_geom.py` | D6 朝向生成、贴边吸附、缝族推导、连通判定 |
| GUI Mixin | `gui/model_editor.py` | 会话状态、事件翻译、调色盘/工具栏/幽灵预览、保存 |
| 桥 | `engine/model_loader.py::load_shapes` | `models/shapes.json` → 调色盘数据源 |

渲染与命中**一行没写**：会话期把 `self.game` 换成实时预览的 `EngineGame`，
块本体完全走既有通用多边形通道（`_polygon_view` / `_draw_polygon_board` /
`SpecPolygonView`），Mixin 只画编辑器专属浮层。

## 2 预览局的 spec 为什么「还原态只有一颗种子」

`_poly_view_origin` 按 `spec.goal_blocks` 定世界原点，而 `load_model` 要求
`tiles` 非空且单一连通——编辑器中途完全可能摆出不连通的半成品。解法：
spec 的还原态恒为**一颗种子块**（原点锚，会话内恒定），当前摆放另走
`Board(spec, blocks)`（`Board` 不查连通性）。朝向表收**整个形状库**的全部像，
玩家换形状不换 spec —— 否则 spec 一换、原点缓存失效、每放一块整盘跳一次。

## 3 四个「不做就会出事」的细节

1. **吸附边表必须用物理整数顶点**（`point + offs`）。用局部 offs 等于假设
   所有块都锚在原点，贴到非原点块时会凭空造出/漏掉候选。
2. **连通判定同样必须用物理顶点**。锚点相对的 offs 会让「两块锚点不同、
   offs 相同」被误判成同一块的两个副本 → 不连通的盘恒判连通，保存门的
   连通检查整个失效（2026-10-25 由 `test/_test_model_editor.py` 抓到）。
3. **计数必须按「当前开着的族」另造 spec**。预览 spec 收的是形状库全部方向
   的族，拿它数移动会让「关掉某条缝族」的开关完全失效。
4. **预览 spec 在会话内必须是同一个对象**。原点缓存按 spec 身份键控，
   每次编辑重建 spec 会让盘面每步跳一次。

## 4 保存门与热注册

保存门（比「高级选项」更严）：**≥1 块 + 单一连通 + ≥2 颗可动**。冻形直接拒存
并说明原因——紧凑 4 块几乎必冻（`engine/editor_geom.py` 的冻形真值）。

保存 = 合成同一份 schema 的 `models/<name>.json` → `model_registry.reload(name)`
→ `_refresh_puzzle_presets()`，菜单里立刻多一项，不用重启。`register_board_type`
拒绝静默覆盖，故 reload 走「先卸后装」；已有文件要**二次点击确认**才覆盖。

编辑器产出与手写文件的唯一差别：`orientations` 一律 `rank: "centroid"`
（质心分侧；锚点 rank 对 bbox 角不是顶点的朝向会错判缝侧），
`solved: "exact"`（逐块还原），`shapes_ref: "shapes.json"`。

## 5 操作与退出语义

> **入口（2026-10-25 迁移）**：不再从谜题菜单进。玩家路径 =
> 右下角「模式」开关 → **创造** → **② 还原状态设计** → **搭积木（自由板型）**。
> 同二级并列的还有格子画布（方/三角/米字，产出样式）、样式库▾、模型库▾
> （列出 `models/` 里已存模型，点一项直接开局——不用绕回谜题菜单）。
> 谜题菜单里原来的「＋ 搭建新模型...」已删除，「模型谜题 ▸」只剩开局项。
> 两种还原态编辑器共用同一套工具条外观与按钮顺序（`gui/editor_chrome.py`）。

**晶格（2026-10-25 新增，左侧面板顶部一行两钮）**：`三角` / `方形`。默认进
三角族（老习惯，形状 `tri`/`iso30`/`half`）；点 `方形` 换成正方形 + 等腰直角
三角（`square`/`rt45`，默认手里是正方形）。**空盘（或只剩种子）才能切**——
两族 basis 不同，混放没有合法坐标；盘上有块时点击只会提示「换晶格得先清空」，
不会悄悄清掉玩家的东西。切族会重建预览 spec 并重新居中（basis 变了，原点缓存
必须失效）。

**左键只管「放」和「拖」**（2026-10-25 用户定案）：

* **单击**（无论落在空白还是**已有块里**）= 放一块。贴边吸附会试形状的**全部
  朝向**（贴哪条边由几何决定），所以相邻点击自动拼成连通的一片；点在块里就是
  「接着这块搭」。吸附半径 0.75 格，吸附不到就自由落在最近格点。
* **按住拖动**（起点在块上）= 移动那块（在捆绑组里就整组一起动）。位移取**整数
  格**——所有块锚点都在整数格上，只要相邻就共享整条边，「坐标差一点自动拼上」
  是晶格对齐的自然结果，不靠额外吸附；与组外块重叠时不应用（块停在最后一个
  合法位置）。起点在空白处拖动 = 平移画布（不放置）。
* **右键**：点块 = 删除；点两块之间的缝 = 捆绑/解绑（同组=刚体整组滑动，与设计
  态点缝同口径）。删除/缝合都放右键，是为了让左键永远不会「点一下块就没了」或
  「想贴着放却变成了捆绑」——这两条都是 2026-10-25 的实测故障。
* **右键拖动 = 框选**（2026-10-28 加，为复制服务）：右键的动作**推迟到松手**才
  执行——按下后位移超过 4px 改判框选，没超过就还是原来的「删块 / 捆绑」。所以
  纯右键点击的语义一字未改。框内**质心**落在框里的块算选中（不用「顶点全在框
  内」也不用「相交」：单元之间互锁，前者会漏选、后者会多选；质心只落在块真正
  所属的那个单元里）。
* **R 旋转 / F 镜像**：鼠标悬停在某块上 → 转**那一块**（绕自身重心转，取最近的
  无重叠落点，±2 格内找不到就拒绝）；悬空 → 转**将要放置**的朝向。
* 滚轮缩放、中键（或左键拖空白）平移；U / Ctrl+Z 撤销（会话内 60 步）；
  侧版面可逐条**开关缝族**（移动计数实时重算）；Enter 激活名字框、再回车保存；
  **[试玩]** = 过保存门 → 保存 → 直接开局；ESC 退出。

**保存门只在保存时检查**（≥1 块 + 整片连通 + ≥2 颗可动）：这两条玩家一眼能看出
来，不必边摆边拦。

**选区 / 复制 / 粘贴 / 阵列**（2026-10-28 加）

要解决的：想把一个「密铺单元」复制成更大的相同密铺图形，得一块块重摆。复制的
单位是**块**——模型文件里没有「单元」这种标记（shatter 的 48 块只是 48 个锚点，
看不出哪几块构成一个单元），所以先框选出构成一个单元的那些块，复制后整体平移
一份。入口三处、键鼠对等：`Ctrl+C` / `Ctrl+V`，或工具条 **[复制] [粘贴] [阵列]**。

* **复制**：框选 → 复制；剪贴板存**相对坐标**（锚点取排序最前那块）+ 形状 / 朝向 /
  相对捆绑号。选区里夹着已被删掉的键会自动滤掉。
* **粘贴**：浮动副本跟鼠标走，整份一起判合法（逐块 `can_place`，一票否决）——放得
  下画绿、放不下画红且点不动。左键点一下落位，ESC 撤掉这一份。落位时记下**这次
  的位移**当阵列周期。
* **阵列**：按「上次粘贴的位移」当方向一，方向二 = 它在**世界坐标**里转一个晶格
  步长（三角 60°、方形 90°），铺 N×M 份。周期**不靠猜形状**——方向一是玩家手动
  贴出来的真实可用间距。每份都过 `can_place`，铺不下就跳过（圈出来的不是平移密
  铺单元时只会少铺几份，不会画出重叠盘面）。
  ⚠️ 方向二必须用 `eg.rotate_vector` 走世界坐标，**不能**用 `eg.rot60` / `rot90`
  ——那两个是标准基的整系数矩阵，套在碎三角那种自定义基 (0.866,0)/(0,0.5) 上
  根本不是 60° 方向（实测位移 (24,0) 被算成 (0,24)，一份都铺不出来）。
* 副本内部保留捆绑，但**每份副本各起新号段**：否则一次剪缝会把所有副本一起剪开。
* 实测（shatter，48 块 / 自定义基 / pos_scale=3）：框选整盘 → 复制 → 贴一份（96
  块）→ 阵列 2×2（192 块 = 4 份），全程无重叠。

**坐标单位（2026-10-25 实测故障）**：渲染通道的世界坐标 = 几何单位 × `cell_size`
（`renderer._polygon_view`）。编辑器内部一切几何量（吸附、落点、命中、缝中点、
幽灵多边形）都以**几何单位**为准，事件入口必须 `screen_to_world(...) / cell_size`
（`_med_screen_to_geom`），绘制出口再乘回去（`_med_geom_to_screen`）。漏这步的
后果是点击位置被放大 60 倍：第二块直接落到屏幕外，画面永远只剩种子那一块，同时
点块删除、点缝、幽灵预览全部失配。测试里也别再拿世界坐标直调 `_med_place_at`
——它的入参是几何单位（早期 24 组测试全绿却不可用，就是因为测试直接喂几何坐标、
绕过了事件层）。

侧栏「盘面」节两个低频操作：**打开模型…** 把已保存的模型读回来续编。续编走
**route A（任意 `basis` + 任意 `pos_scale`，2026-10-27）**——模型自带的朝向表直接
建档，不再要求基归一化到三角/方形标准基：碎三角那种正交不等长基
`(0.866,0)/(0,0.5)`、`pos_scale=3` 也能直接载入。

* **族判定**用 `infer_lattice(doc)`：按**朝向集的世界旋转闭合性**判族，不看基的
  长度比/夹角（后者会把正交不等长基误判成方形）。列表标灰（`_med_load_blocker`）
  与载入（`_med_load_model`）**共用**它——列表说能开就真能开。
* **几何去重 + label_remap**：载入侧按 `normalize(off)` 把同一形状的多种顶点排列
  归一成一类（碎三角 12 个 label 实为 2 个几何朝向的全排列），落块统一用去重下标。
  同时记下每个 label 归一化时减掉的最小角，落块时**加回锚点补偿**——否则不同朝向
  的块各被平移不同的量、整盘拼不连通（2026-10-27 保存往返测试抓到的坑）。
* **旋转/镜像**用 `world_rotate`（世界坐标绕质心转、再换算回整数格），旋转落点用
  `_med_nearest_image` 吸附兜底：自定义基没有整系数 60°/90° 矩阵，标准矩阵法在
  这里不成立。
* **异晶格且盘面 >1 块**时仍拦「需先清空」——一个模型文件只有一个 `basis`，换族要
  清盘是格式约束，不是 UI 限制。

**清空捆绑** 一键解掉所有组——「全捆再逐缝剪」会留下无缝相连的余组（见下），UI 上
没有任何缝可点，只能在这里清。

捆绑的开关语义（`_med_toggle_bundle`）：两侧已同组 → 剪开（只把 `ka` 侧摘出组，
`kb` 侧保留旧组号，可能留下**无缝相连**的余组——与设计态同口径）；否则 → 合并
两侧整组。两个推论：**全盘同组 ⇒ 0 移**（任何缝的另一侧在整个盘面里都是空的，
整组滑出去没有对侧块可推）；剪**内部**缝分出来的那块被刚体三面包围，同样滑不动。

退出时**原样还原**进入前的 game / 相机 / zoom / 三形态旗标。若会话期从菜单另开了
新谜题（`self.game` 被换掉），则**就地收摊而不还原**——把旧局还原回去会覆盖新局。
[试玩] 开局成功时同理：`new_model_puzzle` 返回 True 后**当场** `_med_abandon()`，
不等下一帧绘制（否则那一帧编辑器浮层会画在新局上面）。

## 6 与格子画布共用一套界面骨架（2026-10-25）

两个还原态编辑器功能近似（都是「在盘面上点格 / 点缝摆出还原态」），所以外观也
统一到同一层：`gui/editor_chrome.py` 只做**绘制**，不掺命中判定（热区仍留在各自
模块的 rect 字典里，测试不受影响）：

| 元素 | 共用函数 | 效果 |
| --- | --- | --- |
| 工具条矩形 | `bar_rect(gui, h, left=)` | 右下角悬浮、贴状态栏上沿 8px、同一条宽度算式（`left` = 让位左侧面板）|
| 条底与标题 | `shell(gui, rect, title)` | 半透明深色 + 圆角 8 + 条上方灰色小标题 |
| 按钮 | `btn(gui, rect, text, color)` | 同色板、同圆角 6、hover 统一 +25 |
| 左面板 | `panel_bg` / `section` | 同底色、同分节节奏（标题 + 细线） |

按钮顺序也定死了（从右往左）：**退出 / ▶ 试玩 / 清空 / 存样式（保存）**。
两个编辑器的「第 1 行」放输入与次要操作（画布：m/n/step 参数 + 名字 + 清捆绑；
搭积木：名字 + 撤销），「第 2 行」左侧放状态 / 提示、右侧放主操作——换编辑器时
手指记得住位置。

画布的 [▶ 试玩] 是 2026-10-25 新加的（原来只能存样式再退到首页点样式库）：
**存样式 → 当场按该名字开局**，与搭积木的[试玩]同语义。收摊要点：存完要
`_ann_build_backup = None` 再开局——走 `[退出]` 的还原路径会把刚开的新局盖回旧局。

## 7 方形晶格：引擎零改动，只加了一族（2026-10-25）

加正方形与等腰直角三角形时最担心的「会不会把引擎搞崩」没有发生——**引擎侧
一行没改**。原因是 `editor_geom` 的两族共享同一条不变式：*顶点坐标恒为整数、
朝向像恒为整数顶点*。于是 `poly_of` / `snap_candidates` / 组件判定 / 缝族秩
/ 存档整数锚点全部原样成立，只是把「60° 旋转」换成「90° 旋转」、把「30° 命名
粒度」换成「45°」。

实测（`test/_test_model_editor.py` 的 `t_square_lattice_build` /
`t_square_lattice_save_open`）：2×2 正方形 → 连通、12 条合法移动、过保存门；
再拿两块 `rt45` 同锚点拼出一个正方形 → 推出 `d135` 斜边族（直角三角的斜边只
能配斜边，见 `模型文件_2026-10-24.md` §2.1）；保存落盘 `basis=[[1,0],[0,1]]`、6 块、`d135/h/v` 三族；
`new_model_puzzle` 开局后能真的滑，方向字母表照常派生（A/B/C…）。

新增/改动的函数都在 `engine/editor_geom.py`：`SQUARE_BASIS`、`LATTICES`、
`lattice_info` / `basis_of` / `lattice_of_basis`（按长度比+夹角认族，不吃浮点
噪声）、`rot90` / `mirror_sq`、`d4_images` / `images_of`；其余几何函数统一加
可选的 `basis=` 缺省三角基，老调用零改动。

**一处命名坑**：族的「镜像变换」不能叫 `_med_mirror` ——那是「F 键镜像」的既有
方法名，同名会把 F 键盖掉（一按就 TypeError）。实际叫 `_med_mirror_v` /
`_med_rot_v`（v = vertex）。

## 8 试玩链路（2026-10-25 修通）

`[▶ 试玩]` = **过保存门 → 存模型（热注册）→ `new_model_puzzle(name, 1)` → 就地
收摊**。四步里任何一步失败都不开局：门不过 → 提示差在哪；没名字 → 亮名字框；
同名已存在 → 要求再按一次（防误覆盖）；模型注册失败 → 保存失败、留在编辑器。

开局后这盘是**普通模型局**（`kind = 模型名`，练习模式），操作与「谜题 → 模型谜题
▸」里点开完全一样：点缝选组 → 按住滑块沿缝拖动（模型板型保留「箭头 + 两次
触控」）；**键盘移动（按派生字母键）与 F1 虚拟键盘也已对通用通道开放**——因为
方向字母从几何派生、盘盘不同，键位直接跟这张字母表走（而非写死的 W/A/S/D）。
单次触控角度猜缝仍关死（各板型缝族方向、屏幕落向不同，不做逐板型适配）。
`new_model_puzzle` 里 `control_mouse_kb` 保持 False 即为此故。方向字母由
`compat.direction_table` **从几何派生**（见 `几何引擎.md` 同名段落），玩家看不到
字母，只在状态栏读到「向下左移动 1 步」这类中文方向名。

## 9 自造谜题的模式与「改谜题」（2026-10-26）

> 触发：用户报「自造谜题不能竞速（次要），但**影响是無法進入創造模式**；不能
> 刪、改、查；著色/連鎖/宏定義/求解器/標記這些接口難以統一實現，寧可點鍵時
> 直說『自定義沒這個功能』」。

**模式：创造放开，竞速仍拒。** 拦截只剩 `timed`（`gui/speedrun.py`
`set_game_mode` + `new_model_puzzle` 各一处）：创造首页的两个子入口都**自建
局面**——「① 打乱状态设计 / 格子画布」各自有 `_is_model_kind()` 拒绝，「② 还原
态设计 → 搭积木」用编辑器自己的预览局——与当前盘面形态无关，所以带 `create`
进模型局没有任何丢信息风险。此前 `new_model_puzzle` 把 `timed`+`create` 一起退回
练习，等于让模型局永远进不了创造模式（真 bug）。竞速依旧拒：`export_map` 的方形
分支会把 24 种朝向压成 `#`，存下来的初始局面还原不回同一题，成绩无意义。

**五类接口主动关停（`GUI._model_blocked`，与 `_mi_blocked` 同范式）。** 判据
`_is_model_kind()`（形态键不在旧四形态里），不硬编码 `'shatter'`。关停清单与
理由：分组着色 / 悬停连锁（"相邻"按方形四邻、三角三邻、米字八向手写，模型板型
的缝族与朝向表 per-model，套用会给**错的**着色而不是没信息）；复原提示标记
（走 `find_best_window`，方形口径）；宏（录制/执行都是方形 h/v 缝隙语义，回放
对不上）；求解器（只有 square/triangle/mi 三套语义）。行为：点下去**值不变**，
状态栏给「自造谜题：X 暂不支持（…）」。宏与求解器在**执行入口**拦（
`_start_macro_execute` / `_start_macro_recording` / `_start_auto_solve` /
`_do_solve`），菜单、快捷键、HTTP 三条路共用同一闸门。

**「改谜题」＝把在玩的这局导进搭积木。** 入口：创造 → ② 还原态设计 →
**改当前盘面**（只在模型板型显示，`_ann_btn_blocks_current` →
`_med_open(seed_current=True)`）。与「搭积木（自由板型）」空盘新建并列。
导入规则（`_med_seed_from_model`）：

* `spec.orientations` 只存**标签**，偏移在 loader 闭包里 → 用公开钩子
  `spec.cell_polygon((0,0), label)` 拿平面顶点，再乘 `basis` 逆矩阵、除
  `pos_scale` 解回**整数格偏移**；除不尽就放弃（绝不四舍五入，半格会让整盘
  悄悄挪位）。
* 标签按 `形状:序号` 归并，序号集可带空洞（只存被用到的像）→ 每形状**压缩
  重排**，同时记「旧标签 → 新序号」，块才落得回原位；捆绑组重编号（0 不捆绑）。
* 晶格族从 `spec.basis` 认（`BoardSpec` 新增 `basis` / `pos_scale` 两个带默认值的
  字段，由 `model_loader._assemble` 填——晶格族自此随**板型数据**走，不再只藏在
  闭包里）。
* **族判定与「打开模型…」同口径（2026-10-28 起）**：`_med_seed_from_model` 改用
  `infer_lattice`（按**朝向集的世界旋转闭合性**判族），不再用 `family_of_basis`
  （后者只看 basis 两向量夹角，会把碎三角那种正交不等长基 `(0.866,0)/(0,0.5)`
  误判成方形 → 编辑器按 D4 去转它，转一次就散）。两条路径至此口径统一。
* **形状名**：`spec.orientations` **只有标签**，没有 shape 字段。优先回模型文件查
  （`game.kind` 即模型名 → `model_registry.loaded(kind).doc`）——碎三角的标签是
  **裸号**（`'6'`/`'12'`），只有文件里才记着它属于 `tri` 还是 `iso30`；查不到再
  按 `形状:序号` 解析；都没有才按几何起稳定名（`s0`/`s1`…）。旧代码把裸号当非法
  标签直接退回空盘，碎三角因此根本进不来。
* **会话字段写全**：`med['basis']` 用盘面**自己的基**（不强行换成族的标准基），
  `med['pos_scale']` 写盘面自己的细分度（旧代码漏写、恒为 1 → 粗晶格盘面导入后
  屏幕↔几何差 `ps` 倍，点哪都不中、存回去尺寸也错）。
* 导不进的情形（几何解不回整数格；标签全非法且几何也拿不到；重复键）→
  **退回空盘并在同一条通知里说明**，不静默给残缺盘。

已知取舍：导入后 spec 的缝族由编辑器**从形状边方向重新推导**，不沿用模型文件里
的 `seams`。推导（`derive_families` → `edge_directions`）取**每个方向最短的真实边
向量**当步长（2026-10-27 修：不能除 gcd 退化到 primitive，否则粗晶格/任意基
（碎三角 `pos_scale=3`）的步长会塌到 1/3 块宽、整盘推不出族；标准单位晶格边长
gcd=1，零回归）。碎三角实测：推出来的 6 族（h/v/d30/d60/d120/d150）与文件完全
对应，存回去不再"变宽"。手写模型若定义了**块边之外**的缝族，仍可能与推导结果
不同——这是「板型由几何决定」的既有立场，不额外做缝族搬运。

**补记（同日二次修复）：模式开关是「循环」的，光放开 `set_game_mode` 不够。**
用户验收后仍报「因为不能竞速，导致无法切换到创造模式」。根因不在 `set_game_mode`
（`create` 早已放行），而在 `toggle_game_mode` 的循环顺序 `练习→竞速→创造`：
模型局从练习出发，下一站是竞速被拒 → 函数原地返回 → `game_mode` 一直是练习，
**开关按多少下都到不了创造**。修法：

* 把形态判据从 `set_game_mode` 里提成 `mode_allowed(mode)`（**只判形态，不看计时
  状态**），`set` 与循环开关共用一份——各写一份就必然出现「开关按了没反应，而 API
  能进」的不一致。
* `toggle_game_mode` 沿循环顺序**跳过**进不去的档位，只把允许的下一档交出去；
  真的跳过了档位就在通知尾巴点名（`（本盘型不支持竞速，已跳过）`），不静默跳。
  计时进行中依旧由 `set_game_mode` 拒（循环不越过计时闸门）。
* `_do_set_mode`（HTTP/CLI）失败时转达 `macro_notify_msg` 的真因，不再一律回
  「模式切换失败」。
* 护栏 `_test_model_modes.py` J 组（J0–J7）：模型局按一次直达创造、连按 4 次从不
  落进竞速、跳档有说明、计时中被拒、方形局循环顺序不变。

顺带修掉一处**测试环境污染**：`test/_test_command_palette.py` 与
`test/_test_feature_index.py` 都直接吃 `config/temp_history.json` 恢复上局，若上次
关窗停在模型板型，「着色/连锁/复原标记 切换生效」那几项会被 §9 的闸门拦下而
**假红**。两处已显式 `new_puzzle(...)` 落回方形局（本节验收的是链路，与盘型无关）。

## 10 画风统一：模型板型的渲染参数缺省（2026-10-26）

> 触发：用户报「自造謎題和原先畫風不一致（理論上應該和碎三角完全一致）」。

**根因不在渲染代码分叉**——两者都走通用多边形通道（`_draw_polygon_board`）。
差别只在**板型渲染参数**：`models/shatter.json` 显式写了 `seam_width: 6`
`corner_radius: 3`（6px 缝带 + 圆角），而编辑器存出来的模型（`shield`、`222`…）
没写这两个字段 → 渲染器退回方形旧口径（`gap_width` + 圆角比例）→ 视觉上变成
「块贴块 + 一条黑细线」。实测两张开局截图对比：碎三角是缝带分离 + 圆角，
自造模型是一整片 + 细线。

**修法**：把碎三角那组值定为**模型板型缺省**，并让编辑器存盘时显式写出。

* `engine/model_loader.py`：`DEFAULT_SEAM_WIDTH = 6.0`、
  `DEFAULT_CORNER_RADIUS = 3.0`；`_assemble` 用
  `doc.get('seam_width', DEFAULT_SEAM_WIDTH)`（`corner_radius` 同理）。文件写了
  就仍以文件为准（碎三角的 6/3 不变，手写模型可用 8/4 之类）。
* `gui/model_editor.py` `_med_build_doc`：保存的模型 JSON 显式带这两个字段
  （文件自解释，不依赖 loader 缺省值将来怎么改）。
* 约束照旧：`corner_radius ≤ seam_width / 2`（圆角弧不许越过缝，否则密铺顶点
  戳出放射状尖刺；见 `renderer` 通用通道的注释）。

回归：`test/_test_model_style.py`（A 缺省 6/3、B 显式值优先、C 编辑器存盘带字段、
D 渲染分支与绘制无异常）。

## 11 菜单悬停预览：复原态 + 一种打乱态缩图（2026-10-26）

> 触发：用户提「查的话……能不能每个謎題在菜單欄選擇的時候懸停就有提示，
> 顯示它的復原態和一種打亂態？」

**预览对象是所有预设，不只是模型**（2026-10-26 晚补）：用户报「预览可用了，但
没给所有预设生成预览，而且有些打乱明显不乱、甚至就是复原态」。早先的判据是
「条目 `len==5` 且第 5 项是字符串」，于是异形档位
`('边长4 等级1', 4, 4, 1, 'triangle')` 被当成模型名去查注册表 → 面板写
「预览不可用：'triangle'」。现在统一走 `model_preview.target_of_item(item)`：

| 条目形态 | 目标 |
| --- | --- |
| `('shield（28 块）', 4, 4, 1, 'shield')` | `('model', 'shield', 1)` |
| `('6×6 等级2', 6, 6, 2)` | `('board', 'square', 6, 6, 2)` |
| `('边长6 等级2', 6, 6, 2, 'triangle')` | `('board', 'triangle', 6, 6, 2)` |
| 分组标题 / 分隔线 / 当前行 / 自定义样式 | `None`（不给预览） |

内置 kind 走白名单 `BUILTIN_KINDS`，模型名必须在注册表里；未知 kind 一律 `None`
——**宁可不画，也不画一个错的**。预热清单由 `renderer._preview_targets()` 扫
自己的菜单得出（菜单是「有哪些谜题」的唯一真相），测试里 K1~K6 钉住这套映射。

**打乱态用真引擎、与 GUI 同口径**：`bias=0.3`（`session.shuffle_puzzle` 同值），
步数 `m*n*10` 封顶 `_MAX_ATTEMPTS=120`（10×10 真打乱要 1000 步 ≈ 1s，104px 上
120 步与 1000 步看不出差别）。分片执行：每 10 步 `sleep(3ms)` 让出 GIL，另加
`_TIME_BUDGET=0.6s` 兜底（mi 8×8 每步 ~13ms，240 步要 3s）。全局 31 个预设
首次预热约 5.6s，摊在启动后若干秒里，之后全部命中磁盘。

**「打乱没打乱」必须在拟合之后比**（这条是「打乱态=复原态」的真凶）：
`_fit` 让每张缩图各自按包围盒居中缩放，于是「整块图形平移了一点」在缩图上与
复原态**像素级相同**。早先比的是原始坐标 → 认为「变了」→ 照样存盘。现在
`_polys_scrambled` 用 `_shape_set(_fit(...))` 比归一一遍，一样就**换一局重打**
（`_SCRAMBLE_TRIES=3`），仍一样才抛 `ValueError('这块板打乱后与复原态一样')`，
面板显示「预览不可用：…」——绝不拿复原态冒充打乱态。

**磁盘签名带算法版本**：`<目标>.<内容哈希>.v<CACHE_VER>.<尺寸>.<配色哈希>`。
签名里少了版本号时，算法换了而签名不变，预热看到文件就跳过 → 旧图（包括当年
那张「== 复原态」的 createtest）一直留在盘上。`_purge_stale()` 在预热开始时清掉
命名里没有当前版本号的文件。

**取形走公开钩子，不碰闭包**：`spec.cell_polygon(point, orient)` 给出该块的平面
多边形，与通用渲染通道（`SpecPolygonView.unit_polygon`）**同一数据源**，所以缩图
里的块形状与接缝走向与真盘一致。

**块色与真盘同色（2026-10-26 改）**：一度按块序上青→紫渐变，理由是「单色下两张
图太像」。后来实测单色下两图像素差 26~37%（`222` 0.340 / `createtest` 0.265 /
`shatter` 0.329 / `shatter_lattice` 0.366 / `shield` 0.368），本来就分得清；而
28 色渐变与「自造谜题画风要和碎三角一致」直接冲突。故**取消渐变**，块色一律
`colors['block']`，缝线 `colors['gap']`，底色 `colors['background']` —— 缩图与
真盘是同一套三种颜色（护栏：`_test_model_preview` C1/C2）。

**绘制用真盘同款两趟画法**：先全填、再全描 1px（缝色取 `colors['gap']`）。
逐块「填+描」会被后画那块的填色吃掉半条描边，100px 下就是每条边粗细不一。

**每张缩图各自适配包围盒**（`_fit`）：打乱后块会散开到 1.5–3 倍，共用比例尺会把
复原态压成中间一小坨。缩图要的是「看清这题长什么样」，不是比绝对大小。

**两级缓存，分工不能混（2026-10-26 事故后重划）**：
`_pics` = 纯 Python 的像素多边形（后台线程算），`_surfs` = `pygame.Surface`
（**只许主线程建**）。早先把「建 Surface + `draw.polygon`」放在后台线程里，
真实显示环境下与主线程的绘制/flip 撞车 → 悬停即崩。后台只算几何就没有这个问题。

**空闲预热 + 落盘复用（2026-10-26 用户方案）**：与其悬停现算，不如开局后空闲时
把所有档位的两张图都算好导出。`pump()` 每帧调一次（主循环里 `_preview_pump()`）：
①启动 1.0s 后才起预热线程（避开开局那一下）；②后台逐个算像素多边形，档位之间
睡 120ms 让路（实测最坏帧 128ms → 13~30ms）；③主线程每帧最多「画 + 存」一个。
落盘位置 `<config>/preview_cache/<目标>.<内容哈希>.v<版本>.<尺寸>.<配色>.{goal,scr}.png`。

- **签名用内容哈希**，不用文件 mtime：编辑器存盘会重写文件（mtime 必变）但内容
  可能没变；拷贝/回滚又会让 mtime 倒退而内容其实变了。模型取 `LoadedModel.hash()`，
  内置板型取「复原态各块 `(point, orient)`」的哈希（板型定义一改哈希就变）。
- **标签里必须带 step**（`model_shield_s2`、`board_square_6x6s2`）：等级1/等级2
  是同一块板的两种打乱，内容哈希相同，漏了 step 就共用一个文件名互相覆盖，
  预览只能随机显示其中一级（2026-10-26 实测 31 个目标只落了 26 对）。
- 第二次启动连算都不算：预热发现磁盘签名命中就跳过，悬停只 `pygame.image.load`。
- 目录跟着 `log_writer.log_paths()[0]` 走（打包后退 APPDATA/temp），与日志同一套
  可写性规则，不会在 Program Files 里炸。

**失败不静默 + 不许连累整帧**：模型文件坏掉 / 打乱抛异常 → `(None, None)` + 原因存
`last_error(target)`，菜单画「预览不可用：<原因>」；异常本身写进 `error_log.jsonl`
（带 traceback）。外壳 `_draw_hover_preview` 再包一层 try：预览是可选装饰，
任何内部故障只允许「没有预览」，**绝不能打断主循环**。

**版式**：两张 104px 并排 + 标签（复原态 / 打乱态），面板 232×160，放在二级菜单
右侧；右侧塞不下（`screen_w` 不够）翻到一级菜单左边，两级都塞不下贴右边缘。
一级菜单外框记在 `self.puzzle_menu_rect`（翻边定位用）。
色键一律用调色板里真有的名字，且提示文字用 `colors.get(...) or colors['menu_text']`
兜底——2026-10-26 写了不存在的 `'unsolvable'`（真名是 `'unsolved'`），
悬停任何「算不出来」的条目就 KeyError，表现正是「一碰预览就崩」。

**实测（2026-10-26 晚，全部 31 个档位）**：全部出图，两张图像素差 0.28~0.77
（矩形/米字/数字 0.6~0.77；三角 0.30~0.36，因为块只能在固定三角域内互换，
轮廓天生变化小；模型局 0.28~0.46）。

回归：`test/_test_model_preview.py`（41 项：能算 / 几何同源含「没转置没拉伸」/
块色与真盘一致 / 缓存与异步 / 磁盘预热与复用 / 失败不静默且不连累整帧 /
调色板键静态扫描 / 菜单接线含翻边 / 方形局护栏 / **所有档位都有预览且打乱态≠
复原态** / 版本号与旧图清理）。

`GET/POST /screenshot`（`http_server.py`，external 控制开启 + Bearer token），
无头脚本也能 `draw_board()` 后 `pygame.image.save`（见 `test/_shot_bandaged_play.py`）；

## 13 数字谜题预览的编号（用户 2026-10-26 提，2026-10-29 落地）

数字档位的缩图现在**带编号**：4×4 / 6×6 / 8×8 三档、复原态与打乱态都画，看得出
「这是带编号的题」（原先与普通方形一模一样）。落地时定下来的四条：

1. **编号挂在块对象上，不挂位置**（`_assign_numbers` 写 `block.number`）。
   ⚠️ 早以为「`board.blocks` 打乱后顺序不变、下标就是块身份」是**错的**：它是
   **按键排序**的元组，块一动排序就跟着漂。所以两条取形路径统一走适配器的块
   视图 `_polygons_of_game`（编号随对象迁移），`spec.goal_blocks` 那条只用于取
   几何。编号口径 = GUI 真开局（`new_puzzle` 按还原态块序赋 1..K），有测试逐格
   比对护栏。
2. **编号必须在打乱之前赋**：真局也是建局时赋号。打乱之后再按当时块序赋号，
   同一块在两张缩图里会拿到不同的号 —— 那就成了两道不相干的题。
3. **104px 塞不下，所以数字档位单独放大到 288px**（选了上面三条里的 ②）：
   104px 上打乱态每块只剩 6~13px，字号再退也不是字。288 下最挤的打乱态块也有
   ~12.6px，双位数仍可读。代价是这类档位的预览面板更宽（版式本来就是按 thumb
   算的，`renderer._draw_hover_preview_impl` 跟着 thumb 走，`THUMB_SIZE` 只留给
   其余档位）。
4. **两张图「同进同退」**：画不画byn由**两张里更挤的那张**决定（`_min_cell`）。
   打乱态散得更开、`_fit` 各自适配包围盒，它的块比复原态小得多（4×4 等级2 复原
   23.5px / 打乱 9.4px）。逐张各判就会出现「复原态有编号、打乱态没有」，那会被
   读成「打乱把编号弄丢了」—— 与数字谜题的语义恰好相反。宁可两张都不画。

线程与缓存按原计划：`pygame.font` 只在主线程 `_paint` 阶段出现，后台仍只算几何；
`_CACHE_VER` 已 +1（无字的旧图一律失效）。

> 判「字塞不塞得下」要用 `font.size()`（排版口径），不能用 `render().get_size()`
> （含行距留白的表面尺寸）——后者会把 8×8 打乱态的 64 块全判「画不下」且不报错。
> 详见 `docs/agent/踩坑与搁置.md` §六。
