# 矩形谜题向三维扩展方案（正方体单元）

> 2026-11-17 起草并于当日按五方面讨论定稿，同日补入代码层落点。规则 / 数据层现成，
> 渲染 / 交互从头写，求解器最后接。**本文只定方案，未改任何代码；未认领、未排期。**
> 讨论五方面：基础玩法 / 渲染方法 / 后端和代码 / 功能实现顺序 / 验收方法。
> 有三项须先纠正初稿口径：固定视角是**六个面朝向**（不是绕竖轴四档）、
> 缝隙**不画**（用白线预览代替）、**不滑动时可自由旋转**（不是只四档）。
> 2026-11-17 又补一处纠正：六个朝向**各带固定倾斜、不正对**（原写「正对」，见 §2.2）。

## 1. 基础玩法（已对齐）

规则层几乎不用重写——引擎核心是维度无关的。要推广的只是"每个对象从二维换成三维"，
其中四条已拍板：

- **一步怎么走**：三段式不变——选缝 → 选滑块 → 定方向。缝从线变成切面，
  方向从四向变六向，选中片从 4 邻接变 6 邻接连通。整组连通不变量照搬：
  推完断开或重叠即非法。
- **还原判定**：认**所有朝向**的实心长方体；镜像不单列——正方体拼的长方体非手性，
  镜像态与原态全等，自然包含在内。内部有洞不算还原。
- **内部空腔**：玩法层不单独定义、不处理，能否看见交给渲染（拆分 / 透明度滑动条）。
  这是二维没有的新情形——洞可能完全藏在里面，靠渲染暴露。
- **分组与等级**：照搬。同组按 (行 mod 等级, 列 mod 等级, 层 mod 等级)，
  组数 step² → step³；一步仍是整体平移等级的整数倍。等级 1 退化成一组。
- **操作入口**：只留虚拟键盘（画成三条轴六个键）+ 重画箭头，不复用二维箭头样式。
  没选中任何东西时点虚拟键盘六键 = 平移盘面（六个键正好对六方向）——平移不占空白拖动。

## 2. 渲染方法（已对齐）

### 2.1 技术路线

**自写轻量软渲染投影层，不引 3D 库。** 几何是轴对齐单位立方体堆成长方体，
没有曲面 / 纹理 / 骨骼，投影就是矩阵乘，可见面剔除 + 按深度排序（画家算法）足够，
交给 `pygame.draw.polygon`。numpy 做矩阵现成。整条链路只新增"投影模块"一环，
绘制 / HUD / 打包复用。

不取 `pygame.OPENGL` + PyOpenGL 的路：进 OPENGL 模式后现有 draw / blit 全废、
等于连 HUD 一起重写，打包多带 DLL、吃显卡驱动兼容。软渲染的边界也说清：
轴对齐不重叠的立方体画家算法稳；**半透明混色**下排序会出错，这是透明度滑动条缓后的原因。

### 2.2 视角与相机

- 相机姿态内部用**四元数**存：能精确表达六个面朝向（含从上看时哪条边朝屏幕上方，
  这是 roll 自由度，纯 yaw/pitch 在 ±90 俯仰时退化），无万向锁，切朝向时插值吸附。
  姿态唯一真源就是四元数本身，不另存 yaw/pitch（两处口径迟早打架，且 Euler 在极点退化）。
  对外的输入仍可表现为拖动改视角。对照：MC 用的是欧拉角 yaw/pitch
  （夹在 ±89 躲万向锁），但它是第一人称漫游、不需要控制上下视角的朝向。
- **六个朝向，各带固定倾斜、不正对**（2026-11-17 用户当场纠正，原写「正对」作废）：
  三切面族各两朝向，一一对应"从哪边切开看进去"；但六个都偏固定角度（现取 yaw/tilt 各 14°），
  露邻面细边。原因：正对时实心 3×3×3 在屏幕上就是一张二维 3×3，深度全靠猜。
- **自由旋转**：只看不操作 ~~视角分两态互斥——旋转态只响应旋转、不响应选中 / 滑动，
  且不与滑动动画同时发生；必须正向化（转回六个朝向之一）才能单击选缝 / 双击选块 / 滑动~~
  **2026-11-18 用户撤销该口径（临时定下，非最终定稿）**：当初「必须正向化」只是「若渲染/拾取太难就退而求其次」的
  保底设计，实测拾取走的是本帧渲染面 + 画家序，任意姿态天然成立，故**任何姿态下都能
  单击选缝 / 双击选块 / 用六键滑动**，不再要求转回朝向；旋转中也不清掉已有选中（转一下
  再推是正常操作）。仍保留「旋转与滑动动画不同时发生」。斜视角不再有「只能看」的含义，
  缝面变细时靠缝宽像素门槛与拾取容差兜底。
  ⚠️ 用户 2026-11-18 明确：这类与原方案不符的改动是**临时定下的**（取消正向化只是其一），
  不是拍板终稿——三维计划尚未收尾，日后再议时按「临时口径」看待，别当最终结论。
- **移动手势**：左键拖空白 = 旋转；滚轮 = 缩放；没选中时点虚拟键盘六键 = 平移。
- **居中**：定义为质心落在屏幕中心。默认开"跟随质心"抵消整体偏移（兼作三维防偏移口径），
  手动平移后暂停跟随，按"居中"回正并恢复。
- **透视**：低优先、可考虑；默认正交等距。
- **明暗**：非必需——自由旋转自带立体感；好做可加。
- **缺口**：真凹坑肉眼直接可见，渲染层不需专门设计画法（初稿"缺口怎么画"是过度分析，撤销）。
- **界面模式**：无此概念——2026-11-17 已整套移除 `ui_mode`，三维直接用现有样式。

### 2.3 交互（新的拾取设计）

**不画缝隙，靠白线预览指示切面**（初稿的"缝要能看出深度"作废）：

- **单击** = 选切面并出白线预览，可连续单击换缝。缝不画后，第一击实际是
  "点中块的某个面 → 推断所属切面"，白线画成**整个切面的轮廓**（平行四边形面框），不是一条线。
- **双击**（真正的 double click，不是两下单击）= 选中滑块，规则同现有 `select_block`
  （在当前预览切面一侧选连通组）。手势本身区分两件事，消掉"选块还是选缝"的歧义。
  pygame-ce 无原生双击事件，须自做时间窗（约 300ms）+ 位置容差判定，做成可调参数。
- **命中拾取**是三维交互最难的环节：屏幕点对应哪个块 / 哪个面 / 哪条切面，要按深度排序后
  做射线求交。~~正向化限制让固定朝向下的拾取规整可控~~（2026-11-18 撤销正向化后实测：
  拾取用的就是本帧渲染出的面与画家序，斜姿态同样成立，不需要朝向约束）。
- **预览切面**（2026-11-18 用户口径）：与二维同一套视觉语言——**红色**（`colors['line']`），
  半透明填充。遮挡**按逐点射线求交判定**（每个采样格中心沿视线朝相机走，撞到块就不画），
  所以切面整片埋在块里时就真的不画——正视图下只剩缝口那几像素，物理正确；同时把
  **缝两侧的墙面**（真几何，走正常画家序）一起染红，让「刀切在哪一层」在斜视/拆分时
  一眼可读。
- **选中高亮** = 滑块变绿（整片高亮保留，不改成描边）。分组着色低优先，悬停连锁 / 复原标记不做。
- **滑动动画**走渲染层偏移、不碰逻辑坐标（同现有演示动画口径）；旋转与动画互斥。

### 2.4 三维特有的渲染选项 GUI

2026-11-17 用户定：按「是否要边调边看」分两处承载，**不开第四个浮动面板**，也不全塞设置页。

- **右侧栏（常驻贴边，仅三维态出现）**：拆分滑动条（块按各自质心往外散，露出内部）、
  透明度滑动条（同为看内部，缓后）。这两项是「调节型」，价值全在边拖边看——设置框会挡棋盘、
  浮动面板一关就够不着，故挂右侧栏与速度/缩放滑条并排。棋盘可视区本就排除 right_panel_width，
  天然不遮挡，所见即所得。仅当前形态是 cubic 时显示，二维态原样。右侧栏只有 132px，
  放不下时三维态把用不上的二维开关位（连锁 / 复原标记等视觉强化，本方案已定三维不做）让出来，
  不动棋盘可视区计算。
- **设置页新增「三维」专页**：明暗、透视、分组着色（低优先）、双击时间窗、旋转灵敏度、
  正向化吸附强度等「设一次很少动」的项。二维谜题下该页整页置灰、点开给说明（复用求解器页
  `solver_supports` + `unsupported_reason()` 的形态适配先例，不隐藏，保持入口可发现）。
- **登记机制（决定以后会不会烂）**：三维配置走一张声明式表，每条只声明一次
  （键 / 默认值 / 类型 / 范围 / 所属组 / 适用形态），渲染、读写盘、布尔白名单、feature_index
  检索都从这张表生成或校验。二维「加一个开关动 8 处」是历史包袱，三维从第一天就表驱动，
  避免配置越堆越多后漏同步。
- 绘制网格开关在三维无对象可管，标"不适用"。

## 3. 后端和代码（架构决策）

分三层看：**数据 / 规则层现成只做对拍，新写集中在"看得见、点得着"，真正重写的只有求解器。**

- **★引擎选择：走几何引擎，不改旧引擎 `game.py`。** 硬据：`game.Block.move()` 写死
  `location[0]/[1]`、方向字母 w/s/a/d 二维写死，改它是重写且动到所有形态共用的代码；
  几何侧 `cubic_spec` 已注册（dim=3 / 6 邻接 / 3 缝族 / 48 对称），`compat.py` 坐标换算与
  `anchor_shuffle.py` 的 `dim = len(location)` 都维度无关。用户另点明三维谜题大概只做这一类、
  不用其他形状，更没有为三维去通用化多形态的必要。
- **现成层**：`engine/registry.py` 的 `cubic_spec(m,n,d)` / `cubic_lattice` 已定义上述几何；
  规则层的选组、推、判合法、连通不变量维度无关，与方形 / 三角 / 米字共用。要做的不是重写，
  是与矩形规则做差分对拍。
- **新写三块**：
  - 投影模块——独立新文件，输入逻辑坐标 + 相机状态，输出可见面多边形和深度，
    交给 `pygame.draw.polygon`；不碰现有 `renderer.py`。
  - 交互层——命中拾取、双击判定、三轴六键、重画箭头、白线切面预览；2D 命中带与拖拽用不上。
  - 相机状态——四元数姿态 + 六视角 + 缩放 + 平移 + 质心跟随，**按形态分存 config**
    （见下重启兼容）。
  三维作为新板型走 registry，与方形 / 三角 / 米字并列，2D 渲染路径原样保留。
- **存档 / 历史**：现有存档走 JSON（含 puzzle / history / 校验和），字符网格 `export_map`
  是基本没用的历史遗留。三维要扩的是 JSON 里的坐标字段（加深度维、类型标记 `type: cubic`），
  读档按类型分派、兼容二维旧档；捆绑组信息要不要一并存沿二维现状（二维自身有争议）。
- **重启兼容**：config 里跟形态绑的字段（`camera_x/y`、`zoom`、tutorial）是二维口径。
  按形态分相机组：二维原样留，三维另存一组姿态 / 缩放 / 平移，缺字段用默认；
  gather 参数待三维求解器接时再分组。
- **求解器（重写、放最后）**：查表 / 宏 / 启发式全按二维尺寸构建，搬不过来；状态立方级增长。
  但判胜"认所有朝向"不是额外难题——二维求解器本就找"任意位置的实心矩形"（枚举所有窗口），
  三维对应"枚举所有朝向的窗口"，思路现成。硬仗是查表规模，不承诺二维速度和成功率。
- **防偏移口径**：二维"求解器消整体平移 + 回放按渲染位置逐帧补偿"在三维失效，
  留到接求解器时定稿；第 3 阶段先按"跟随质心"够用。

- **第 6 步 动画**：改 `gui/animation.py`，走渲染层偏移、不碰逻辑坐标。
- **后期四块**（求解器 / 创造模式 / 宏 / 防偏移）不预判，推进到那步再单独规划。

三条贯穿全程的约束：

- **旧功能零影响靠分派点隔离，不靠总开关**：三维是新 kind，建局 / 渲染 / 事件都按 kind
  走新分支，老 kind 一行不改；`engine.config.is_enabled()` 默认关走旧 `game*.py`，
  模型板型（含 cubic）走 `EngineGame` 不受它管；**cubic_spec 没有 cell_polygon，天然进不了
  二维通用渲染通道 `_generic_spec()`**（判据就是 cell_polygon），renderer 三套旧手画路径不动；
  config 按形态分相机组，二维原字段原样留；每步跑现有 239 个测试 + 三项 lint，
  三维新测试用 `_test_cubic_*.py`。
- **接口占位不写空接口骨架**：`gui/feature_index.py` 每个功能带 `forms` / `supports()` /
  `unsupported_reason()`，命令面板搜索会自动显示"三维不支持、仅支持……"——这就是"待更新"
  反馈，把 cubic 加成形态键、只给已实现功能登记即可；按钮 / 菜单先画位置，点击走
  `macro_notify_msg` 提示（`GUI.py` 里三角形"尚未实现"是先例）。HTTP 相反：
  `API_INDEX` 每条被 `_test_external_control.py` 断言有真实分派，挂空端点会红 →
  API 按实现进度逐条加，不先铺。
- **后端 API**：真正新增只有一类——`/camera`（查 / 设六视角、旋转、平移、缩放、正向化），
  二维没有对应物。扩参：`/new`（加 cubic + depth，现 kind 白名单硬编码四形态）、
  `/select_gap`（切面族 r/c/d，现白名单 h/v/p/n/d1/d2）、`/move`（六向）、`/map` 和 `/status`（加深度）；
  扩分析：`/analysis/window|holes|actions|preview`；原样用：undo / redo / shuffle / reset /
  macro / timer / records / file / screenshot / quit（只认 game 对象）。安全点：三维求解器接上前
  `/solve` 和 `/solver/*` 对三维明确回"不支持"，不许拿二维求解器硬算。新增端点须同步
  `API_INDEX`、`HELP_DETAILS`、分派代码三处（测试逐条断言）。

## 5. 功能实现顺序（六阶段）

原则：**先把"没有求解器也能玩通"的闭环打通，求解器放最后。**

1. **规则底座**——立方板型（现成）+ 与矩形对拍。
2. **可玩闭环（核心工作量）**——投影渲染 + 命中拾取 + 单击选缝 / 双击选块 +
   ~~正向化~~ 任意姿态可操作 + 三轴六键。
3. **反馈与接入**——拒绝反馈（三维重做抖动 / 描边 / 声音）、音效、右下角提示、竞速、
   居中与相机手势、三维渲染选项 GUI。
4. **宏机制（求解器地基，提前）**——动作序列精确录制回放；逆序宏三维禁用但保底不崩。
5. **周边功能**——创造模式（三维搭建，参考 MC 的方块放置 / 挖掘）、自定义初 / 高级、捆绑、
   谜题预设档、帮助小改、谜题悬停预览（低优先）。
6. **防偏移 + 求解器（最后）**——相机口径定稿 + 查表 / 宏 / 启发式重写；不承诺二维速度。

视觉增强只保留着色（低优先），连锁 / 标记不做。

## 6. 验收方法（按步骤，产物在游戏内看）

分步骤、每步有可看可验的产物。**产物直接在游戏里看**：先在谜题菜单加
"三维 ▸ 1×1×1 ~ 3×3×3"预设作验证入口，点进去哪怕调用暂未实现的功能报错崩溃也没事
（入口先于功能落地，当脚手架用）。从第 4 步起验收大部分可自动化。

1. **能画出来，看遮挡关系**——几个立方体摆成小长方体，从标准视角渲染。
   盯：前块挡后块、三面可见时哪面朝上、凹坑看得出来。这步不过后面全是空中楼阁。
2. **六视角与自由旋转**——六张朝向图（每面带固定倾斜、邻面露细边，画面规整、朝向一致）+
   一段拖动空白旋转（流畅、准确、不跳变）。判据含：拖动松手不产生选中；
   ~~旋转态下点什么都不该选中（互斥）~~（2026-11-18 撤销：斜姿态下点选也生效，见 §2.2）。
3. **能正确选中**——单击出切面预览、双击选中滑块；选中组正确、预览切面轮廓正确
   （预览为红色半透明面 + 轮廓，与块有遮挡关系；任意姿态可点，包围盒平面不选）。
4. **真的能玩的起步**——选中后能滑动，虚拟键盘六键 + 重画箭头到位，能打乱、能判胜。
   从这里起验收大部分适合自动化（走步序列 / 集合比对）。
5. **历史记录**——撤销 / 重做 / 自动历史 / 存档载入；三维坐标、兼容二维旧档。
6. **动画**——滑动动画走渲染偏移不碰逻辑，与旋转互斥。
7. **后续（待细化）**——反馈与接入（拒绝三件套 / 音效 / 右下提示 / 竞速 / 渲染选项 GUI）、
   宏机制、周边功能、防偏移与求解器。求解器用成功率与墙钟同时报，不单看一个。

每阶段验收落在可对比产物：遮挡与视角靠游戏内肉眼确认，走步与历史靠可复现序列，
求解器靠成功率 + 墙钟。
