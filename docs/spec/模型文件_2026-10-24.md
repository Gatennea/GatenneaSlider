# 模型文件（静态定义板型）实施计划

> 2026-10-24 定稿。目标：**新增板型不再改 Python**，丢一个 JSON 进目录即可玩；
> 最终让玩家在游戏内用已有滑块拼装配置、保存成模型文件。
>
> 本文只描述要做的事与验收口径。已完成的碎三角改造见
> `docs/spec/GUI解释器化接入计划_2026-10-23.md` 的修订 R1。

---

## 一、目标与非目标

**目标**

1. 板型 = 数据：形状 + 放置 + 朝向 + 缝族 + 步长，全部可从文件读取。
2. 加载即校验：写错的模型在加载时报错，而不是给玩家一个玩不了的盘。
3. 原版四谜题**运行路径一行不动**（见「双后端」）。

**非目标**

- 游戏内自由画多边形（只从形状库选，避免出现无法密铺的自定义形状）。
- 把原版四谜题改成文件驱动（可另写文件做对拍测试，但不进运行时）。

## 二、两层文件

### 2.1 滑块库 `models/shapes.json`

只放**原子形状**（不能再拆成库内形状的）。组合形状（菱形、长方形、六边形）
交给自由捆绑，不占形状位。

顶点用**整数格坐标**声明，`basis` 把格坐标映射到平面（行向量，浮点只在
这一层出现）。一个模型只允许一套 basis，所有形状顶点在该 basis 下必须是整数。

每个形状还要声明它在**哪套晶格**上（`lattice`，2026-10-25 起）：

```json
{
  "schema": "gatenna.shapes/1",
  "shapes": {
    "tri":    {"lattice": "tri",    "verts": [[0,0],[1,0],[0,1]]},
    "iso30":  {"lattice": "tri",    "verts": [[0,0],[1,0],[1,1]]},
    "half":   {"lattice": "tri",    "verts": [[0,0],[2,0],[1,1]]},
    "square": {"lattice": "square", "verts": [[0,0],[1,0],[1,1],[0,1]]},
    "rt45":   {"lattice": "square", "verts": [[0,0],[1,0],[0,1]]}
  }
}
```

晶格定义（basis / 对称群 / 缝族命名角粒度）在 `engine/editor_geom.py` 的
`LATTICES`，形状库只写族名：

| 族 | basis | 旋转 | 缝族角粒度 | 形状 |
|---|---|---|---|---|
| `tri` | `e1=(1,0) e2=(½,√3/2)` | 60°（D6） | 30° | `tri` 正三角、`iso30` 30-60-90、`half` |
| `square` | `e1=(1,0) e2=(0,1)` | 90°（D4） | 45° | `square` 正方形、`rt45` 等腰直角 |

> 旧格式（形状直接给**裸顶点数组**）仍然收，一律当 `tri` 族——那是 v1 唯一
> 存在的晶格。`load_shapes()` 仍返回 `{名: 顶点}`（老口径），要族信息用
> `load_shape_lib()`。

**为什么正方形 / 等腰直角三角必须另起一族**（不是没实现，是数学上放不进三角
晶格）：三角晶格上的长度平方只取 `p²+pq+q²` 型的值（1, 3, 4, 7, 9…），
**没有 √2**——等腰直角的斜边要 √2；而正方形要求 90° 旋转是格自同构，三角晶格
的自同构是 60° 的倍数，90° 落不到格上。所以两者都得换 basis。
代价是：**同一盘面只能一族**（模型文件只有一个 basis），方形块与三角块不能混在
一个模型里——这是格式约束，GUI 层的「晶格」切换因此必须清盘。
`rt45` 的斜边长 √2，与正方形边长 1 不匹配；`snap_candidates` 要求「两端点分别
相等」（整条边贴合），所以斜边只能配斜边、直角边只能配直角边——**不同长度的边
拼不上是定义的自然结果，不是额外规则**。

### 2.2 模型定义 `models/<name>.json`

```json
{
  "schema": "gatenna.board/1",
  "name": "shatter",
  "title": "碎三角",
  "engine": "geometric",
  "basis": [[1, 0], [0.5, 0.8660254037844386]],
  "tiles": [
    {"p": [0, 0], "o": "1", "g": 0},
    {"p": [2, 0], "o": "2", "g": 0}
  ],
  "shapes": {"1": "tri", "2": "iso30", "...": "..."},
  "orientations": {"1": {"shape": "tri", "angle": 0, "mirror": false}},
  "seams": [
    {"name": "h",   "coeffs": [0, 1], "step": [6, 0]},
    {"name": "d30", "coeffs": [-1, 1], "step": [3, 3], "rank": "centroid"}
  ],
  "view": {"rotate": 180, "mirror": false}
}
```

| 字段 | 含义 |
|---|---|
| `engine` | `geometric`（几何引擎维护，自带缝族/步长）或 `native`（原版板型 + 样式） |
| `basis` | 格坐标 → 平面的 2×2 行向量矩阵 |
| `tiles` | 放置表：位置 + 朝向标签 + 组号（`g` 省略 = 不捆绑） |
| `orientations` | 朝向标签 → 形状 + 旋转角 + 是否镜像 |
| `seams` | 缝族：`coeffs`（线法向，rank = coeffs·顶点）+ `step`（沿缝平移方向，与 coeffs 正交；加载时规范成 (step, −step) 一对，**符号不载语义**）。可选 `rank`（见下） |
| `rank` | **可选**缝族分侧口径：省略 = 锚点 rank（`coeffs·point`，方形/粗晶格够用）；`"centroid"` = 质心 rank（`coeffs·顶点均值`，浮点）。**朝向形状的 bbox 角不一定是顶点时锚点 rank 会错判缝侧**——典型是三角晶格 ▼（offs (0,1),(1,0),(1,1)，锚点 (0,0) 在块外）：n 族缝沿 ▲▼ 共享斜边走，两块必须分居缝两侧，锚点 rank 把 ▼ 错放下侧。引擎 tri preset 的 `rank_n` 钩子就是补这个洞；`centroid` 是它的形状无关推广（对任意凸块，缝穿某边时质心必严格居其一侧）。**搭积木编辑器产出的模型一律 `centroid`**；实测与 tri preset 的「h/p 朴素 + n 挂钩子」逐项等价（k=3 移动集 12/12 全等） |
| `seam_width` | **可选**渲染参数：缝宽（设计像素）。块内缩半个缝宽画上去，中间让出这条缝；**缝带露出背景色、不填灰**，灰色只沿格子真实边界画一条细线——密铺板型的缝正是「缝延长构成的晶格」。省略 = 退回渲染器 `gap_width`（4px） |
| `corner_radius` | **可选**渲染参数：圆角半径上限（设计像素）。**须 ≤ `seam_width`/2**，否则削圆角的弧越过缝、在密铺顶点戳出尖刺。省略 = 退回渲染器旧口径（≈5px，再按最短边 8.3% 收） |
| `view` | 仅显示层：`rotate` 0/90/180/270 + `mirror`（绕水平轴翻） |

两个渲染参数都是**板型身份的一部分**（跟 `solved` 同级），因为它们的合适取值由
密铺几何决定、不是全局口味：方块 90° 角用 5px 圆角配 4px 缝就够；
碎三角是 60° 密铺，同样的圆角半径在顶点张开的口子大得多，
必须给更宽的缝才装得下（当前 `seam_width: 6, corner_radius: 3`）。
调参时先定 `corner_radius`，再令 `seam_width ≥ 2 × corner_radius`。

**缝里不要填灰**：缝带露出背景色，灰色只用来画那条晶格线
（用户 2026-10-25 定：「沒有滑塊的地方別全部填充灰色，灰色按理來說只是縫隙畫線」）。
缝一加宽、若整条缝填成灰，整盘就发灰。

四形态现已统一到这个口径：
- **方形**：本来就只画线，从未整片填灰。
- **三角 / 米字**：2026-10-25 移除「顶点补灰封底」（旧 `_seal`，用未内缩的精确
  形状整片铺 gap 灰）＝用户认可的样式（2026-10-23 那版）。纯画线会在顶点留下
  放射状深色星芒（60° 六块、米字八块交会时尤其明显），**当前状态是接受它**
  （用户 2026-10-25 拍板「就这样」）。曾在顶点画灰圆「补晶格节点」被用户判
  「画蛇添足」已彻底删除——顶点就是线交会的样子，不再多画任何形状；日后若要
  收掉星芒，唯一非装饰手段是调小圆角半径（三角 r≈3、米字 r≈2）让顶点缺口
  回到方形量级，代价是圆角变含蓄。
- **碎三角等模型板型**：同口径（见上）。

`native` 模型不带 `seams`/`orientations`，改为引用原版板型
（`"native": {"preset": "mi", "style": "<样式名>"}` 之类），由原版路径接管。

## 三、定稿的设计决定

1. **原子形状**：库里只放不可再分的；组合形状用捆绑（60° 菱形 = 2 正三角）。
2. **步长作者写、引擎验**：加载时枚举合法候选（平移后仍严丝合缝），文件里的值
   必须在候选内，否则报错并列出候选。`step > 1` 必须逐格验中途位置。
3. **双后端**：原版四谜题永远走原版快路径；模型文件导入走几何后端（认慢）。
4. **新板型操作方式（2026-10-25 修正）**：默认只支持「箭头 + 两次触控」；
   但方向字母已从几何**派生**（`compat.direction_table` 第二级来源，盘与盘不同），
   于是**键盘移动（按派生字母键 A/B/C…）与 F1 虚拟键盘**对通用通道重新开放
   （面板即这套键盘映射的 GUI 形式，与新增键盘移动同源）。单次触控（拖拽角度
   猜缝）仍关死——各板型缝族方向、屏幕落向不同，不做逐板型适配。
5. **方向字母不写进文件**：按落屏方向自动分配（因为只支持箭头）。
6. **`view` 走显示层**：不动数据，故不影响缝、步长、存档。
7. **不做自由画多边形**；六边形不是加形状能解决的（实测 408 候选全半路碰撞）。

## 四、加载流程

```
读 JSON → 结构校验（字段/类型/范围）
        → 形状解析（顶点 → basis → 平面多边形）
        → 朝向展开（标签 → (形状, 旋转, 镜像) → 多边形）
        → 放置表解析（去重、越界、组号）
        → 缝族解析（线方向 → rank 泛函；步长 → 候选校验）
        → 物理公理校验（见下）
        → 组装 BoardSpec → 注册进 registry
```

**物理公理（全部必须在加载期跑）**

| # | 公理 | 判据 |
|---|---|---|
| A0 | 还原态自洽 | 无重叠、单一连通、块数 = `tiles` 条数 |
| A1 | 缝是真缝 | 每条缝的线**整条**落在块边上，不劈开任何块 |
| A2 | 缝可滑 | 沿缝平移一个步长，途中每个中间位置都不重叠（逐格，不是只查首尾） |
| A3 | 每步可逆 | 任一步沿反方向能精确推回；两侧非空 |

任一条不过 → 抛错并指出「哪个字段 / 哪条缝 / 哪两块」。

## 五、存档

- `geometric` 模型局：快照存**稀疏 `tiles` 三元组**（`[p, o, g]` 排序），不存矩阵。
  理由：矩阵是包围盒的稠密快照，实测碎三角打乱一次就从 2098 字节涨到 4915 字节，
  而信息只有 48 个三元组。
- 存档头带模型身份：`{"model": {"name", "schema", "hash"}}`。hash 不一致 →
  只读打开并明确提示；模型缺失 → 直接拒绝，**绝不回退成方形**。
- **编辑器预览局绝不进存档**（2026-10-25）：搭积木会话期 `self.game` 的
  `kind` 是哨兵 `PREVIEW_KIND = '__editor__'`（`gui/model_editor.py`），它没有
  也不该有 `models/__editor__.json`。三道闸：
  1. `save_config`（退出自动存）检测到 `_med_active` → **不写** temp_history，
     保留进入编辑器之前的那个真实局面；
  2. `Ctrl+S` / 另存为 → `_med_save_blocked()` 直接拒（编辑器自己的落盘口是
     [存样式] → `models/<名>.json`）；
  3. 载入端读到 `type: '__editor__'` → 抛 `StaleEditorSave`，启动时**安静忽略**
     （不是「模型未安装」——那条报错会每次启动弹一次）。
     旧版本已经写脏的 temp_history 就是靠第 3 条痊愈的，不需要手工删文件。
- 老五形态的 `matrix` 格式一行不动。

## 七、实施记录（2026-10-24）

### 7.1 已落地的文件与入口

| `models/shapes.json` | 原子形状库（三角族 `tri`/`iso30`/`half`，方形族 `square`/`rt45`） |

| `experiments/_probe_model_editor.py` | 编辑器逻辑路径探针（stub 掉 GUI，无窗口） |

### 7.2 三个「不做就会出事」的细节

1. **朝向顺序是盘型身份的一部分**。`adapter.update_matrix` 把朝向下标写进
   快照 matrix（值 = 下标+1）。若文件里的 `orientations` 顺序与代码版不同，
   同一盘型的旧存档读出来块的角色会整体错位。故加载器**按文件书写顺序**
   建 `spec.orientations`（不做字典序排序），生成器也按 `spec.orientations`
   输出，并有用例钉住「与代码版顺序相同」。
2. **劈块判据必须看边，不能看 rank 区间**。直线 `{rank=t}` 过三角形某个
   顶点时并没有劈开它；用 `min<t<max` 会把这种情形误判成劈块（碎三角的
   等腰三角存在 rank 为 `{0,3,6}` 的角色）。
3. **缓存是必须的，不是优化**。文件版起初没有缓存，一次打乱 7.6s（代码版
   有 `lru_cache`，一直 0.77s）。缝线/顶点/连通分量三处按局面缓存后
   0.63s，比代码版还快。

### 7.3 与计划的偏离（如实记录）

- **存档没改成稀疏 `tiles`**。当前 matrix 编码（值 = 朝向下标+1）在碎三角
  上是**无损**的（位置是质心晶格整数、朝向是下标），实测还原态与打乱 40 步
  的局面往返都逐块一致。稀疏格式的收益只是体积（4915 → 约 1500 字节），
  而代价是存档要分两条格式并存。先按「能用且不丢信息」落地，稀疏化留待
  有体积压力时再做。
- **模型身份 hash 只提示不拒绝**。hash 不一致 = 模型文件改过，旧档仍尽量
  读出来并提示「朝向可能有偏移」。只有**模型缺失**才拒绝（绝不回退方形）。
- **`solved` 字段**：文件可选 `"solved": "exact" | "canonical"`，默认
  `canonical`（引擎既有语义）。碎三角写 `exact`（拼图语义，整盘旋转不算还原），
  与代码版 `_solved_check` 一致。

### 7.4 S6 对拍结果（2026-10-24）

目的：证明「丢一个 json 就多一个板型」对**非碎三角**也成立。碎三角本就是为这套
schema 设计的，它通过了不代表 schema 有普适表达力；原版方形/三角才是硬骨头。

探针文件落在 `experiments/model_probe/`（**不在 `models/`**，不会被运行时注册成真板型），
由 `experiments/_gen_model_probe.py`（方形）与 `experiments/_gen_model_tri.py`（三角）生成，
测试 `test/_test_model_probe.py` 对拍。对拍口径**只比几何**：
还原态块多边形集合、legal_moves(1) 条数、1 步可达局面集合、2 步可达局面集合
（后两项比条数强得多，能抓出「条数同但走向不同」）。不比块键/缝族名（形态本来允许不同）。

| 板型 | 块数 | legal_moves(1) | 1 步可达 | 2 步可达 | 还原态几何 |
|---|---|---|---|---|---|
| 方形 4×4 | 16 | 24 | — | — | 全等 |
| 方形 6×6 | 36 | 40 | — | — | 全等 |
| 三角 k=6 | 36 | 48 | — | 1669 个（文件=代码） | 全等 |

结论：schema 已用三种**几何上互不相同的**密铺验证——矩形（无朝向、2 缝族）、
碎三角（复杂非规则密铺）、三角（斜坐标晶格 + C2 朝向）。米字/数字依赖手写渲染路径、
运行时无收益，故不写文件。至此「文件驱动板型」的表达力证据齐备，S6 收尾。
此节与 §8.2（米字渲染路径）一致：米字/数字不在文件驱动范围。


## 八、搭积木编辑器（2026-10-25 落地）

§一 写的「最终让玩家在游戏内用已有滑块拼装配置、保存成模型文件」由本节收口：
**玩家不再手写 JSON**，进 GUI 摆积木即可，保存动作在幕后合成同一份 schema。

入口：**谜题 → 模型谜题 ▸ → 「＋ 搭建新模型...」**。

### 8.1 三段分工

| 层 | 文件 | 职责 |
|---|---|---|
| 纯逻辑（零 pygame，可单测） | `engine/editor_geom.py` | D6 朝向生成、贴边吸附、缝族推导、连通判定 |
| GUI Mixin | `gui/model_editor.py` | 会话状态、事件翻译、调色盘/工具栏/幽灵预览、保存 |
| 桥 | `engine/model_loader.py::load_shapes` | `models/shapes.json` → 调色盘数据源 |

渲染与命中**一行没写**：会话期把 `self.game` 换成实时预览的 `EngineGame`，
块本体完全走既有通用多边形通道（`_polygon_view` / `_draw_polygon_board` /
`SpecPolygonView`），Mixin 只画编辑器专属浮层。

### 8.2 预览局的 spec 为什么「还原态只有一颗种子」

`_poly_view_origin` 按 `spec.goal_blocks` 定世界原点，而 `load_model` 要求
`tiles` 非空且单一连通——编辑器中途完全可能摆出不连通的半成品。解法：
spec 的还原态恒为**一颗种子块**（原点锚，会话内恒定），当前摆放另走
`Board(spec, blocks)`（`Board` 不查连通性）。朝向表收**整个形状库**的全部像，
玩家换形状不换 spec —— 否则 spec 一换、原点缓存失效、每放一块整盘跳一次。

### 8.3 四个「不做就会出事」的细节

1. **吸附边表必须用物理整数顶点**（`point + offs`）。用局部 offs 等于假设
   所有块都锚在原点，贴到非原点块时会凭空造出/漏掉候选。
2. **连通判定同样必须用物理顶点**。锚点相对的 offs 会让「两块锚点不同、
   offs 相同」被误判成同一块的两个副本 → 不连通的盘恒判连通，保存门的
   连通检查整个失效（2026-10-25 由 `test/_test_model_editor.py` 抓到）。
3. **计数必须按「当前开着的族」另造 spec**。预览 spec 收的是形状库全部方向
   的族，拿它数移动会让「关掉某条缝族」的开关完全失效。
4. **预览 spec 在会话内必须是同一个对象**。原点缓存按 spec 身份键控，
   每次编辑重建 spec 会让盘面每步跳一次。

### 8.4 保存门与热注册

保存门（比「高级选项」更严）：**≥1 块 + 单一连通 + ≥2 颗可动**。冻形直接拒存
并说明原因——紧凑 4 块几乎必冻（`engine/editor_geom.py` 的冻形真值）。

保存 = 合成同一份 schema 的 `models/<name>.json` → `model_registry.reload(name)`
→ `_refresh_puzzle_presets()`，菜单里立刻多一项，不用重启。`register_board_type`
拒绝静默覆盖，故 reload 走「先卸后装」；已有文件要**二次点击确认**才覆盖。

编辑器产出与手写文件的唯一差别：`orientations` 一律 `rank: "centroid"`
（质心分侧；锚点 rank 对 bbox 角不是顶点的朝向会错判缝侧），
`solved: "exact"`（逐块还原），`shapes_ref: "shapes.json"`。

### 8.5 操作与退出语义

> **入口（2026-10-25 迁移）**：不再从谜题菜单进。玩家路径 =
> 右下角「模式」开关 → **创造** → **② 还原状态设计** → **搭积木（自由板型）**。
> 同二级并列的还有格子画布（方/三角/米字，产出样式）、样式库▾、模型库▾
> （列出 `models/` 里已存模型，点一项直接开局——不用绕回谜题菜单）。
> 谜题菜单里原来的「＋ 搭建新模型...」已删除，「模型谜题 ▸」只剩开局项。
> 两种还原态编辑器共用同一套工具条外观与按钮顺序（`gui/editor_chrome.py`）。

**晶格（2026-10-25 新增，左侧面板顶部一行两钮）**：`三角` / `方形`。默认进
三角族（老习惯，形状 `tri`/`iso30`/`half`）；点 `方形` 换成正方形 + 等腰直角
三角（`square`/`rt45`，默认手里是正方形）。**空盘（或只剩种子）才能切**——
两族 basis 不同，混放没有合法坐标；盘上有块时点击只会提示「换晶格得先清空」，
不会悄悄清掉玩家的东西。切族会重建预览 spec 并重新居中（basis 变了，原点缓存
必须失效）。

**左键只管「放」和「拖」**（2026-10-25 用户定案）：

* **单击**（无论落在空白还是**已有块里**）= 放一块。贴边吸附会试形状的**全部
  朝向**（贴哪条边由几何决定），所以相邻点击自动拼成连通的一片；点在块里就是
  「接着这块搭」。吸附半径 0.75 格，吸附不到就自由落在最近格点。
* **按住拖动**（起点在块上）= 移动那块（在捆绑组里就整组一起动）。位移取**整数
  格**——所有块锚点都在整数格上，只要相邻就共享整条边，「坐标差一点自动拼上」
  是晶格对齐的自然结果，不靠额外吸附；与组外块重叠时不应用（块停在最后一个
  合法位置）。起点在空白处拖动 = 平移画布（不放置）。
* **右键**：点块 = 删除；点两块之间的缝 = 捆绑/解绑（同组=刚体整组滑动，与设计
  态点缝同口径）。删除/缝合都放右键，是为了让左键永远不会「点一下块就没了」或
  「想贴着放却变成了捆绑」——这两条都是 2026-10-25 的实测故障。
* **R 旋转 / F 镜像**：鼠标悬停在某块上 → 转**那一块**（绕自身重心转，取最近的
  无重叠落点，±2 格内找不到就拒绝）；悬空 → 转**将要放置**的朝向。
* 滚轮缩放、中键（或左键拖空白）平移；U / Ctrl+Z 撤销（会话内 60 步）；
  侧版面可逐条**开关缝族**（移动计数实时重算）；Enter 激活名字框、再回车保存；
  **[试玩]** = 过保存门 → 保存 → 直接开局；ESC 退出。

**保存门只在保存时检查**（≥1 块 + 整片连通 + ≥2 颗可动）：这两条玩家一眼能看出
来，不必边摆边拦。

**坐标单位（2026-10-25 实测故障）**：渲染通道的世界坐标 = 几何单位 × `cell_size`
（`renderer._polygon_view`）。编辑器内部一切几何量（吸附、落点、命中、缝中点、
幽灵多边形）都以**几何单位**为准，事件入口必须 `screen_to_world(...) / cell_size`
（`_med_screen_to_geom`），绘制出口再乘回去（`_med_geom_to_screen`）。漏这步的
后果是点击位置被放大 60 倍：第二块直接落到屏幕外，画面永远只剩种子那一块，同时
点块删除、点缝、幽灵预览全部失配。测试里也别再拿世界坐标直调 `_med_place_at`
——它的入参是几何单位（早期 24 组测试全绿却不可用，就是因为测试直接喂几何坐标、
绕过了事件层）。

侧栏「盘面」节两个低频操作：**打开模型…** 把已保存的模型读回来续编（朝向按
`normalize(off)` 与形状库**几何匹配**，不要求 label 同名；basis 先按几何不变量
（两基向量长度比 + 夹角）**认出属于哪一族**：同族直接载入，异族则在盘面为空时
自动切族后载入、盘上有块时明确拒绝并提示先清空；认不出的基（碎三角那种
(0.866,0)/(0,0.5)）与 `pos_scale≠1` 的模型仍明确拒载）；**清空捆绑** 一键解掉所有组——
「全捆再逐缝剪」会留下无缝相连的余组（见下），UI 上没有任何缝可点，只能在这里清。

捆绑的开关语义（`_med_toggle_bundle`）：两侧已同组 → 剪开（只把 `ka` 侧摘出组，
`kb` 侧保留旧组号，可能留下**无缝相连**的余组——与设计态同口径）；否则 → 合并
两侧整组。两个推论：**全盘同组 ⇒ 0 移**（任何缝的另一侧在整个盘面里都是空的，
整组滑出去没有对侧块可推）；剪**内部**缝分出来的那块被刚体三面包围，同样滑不动。

退出时**原样还原**进入前的 game / 相机 / zoom / 三形态旗标。若会话期从菜单另开了
新谜题（`self.game` 被换掉），则**就地收摊而不还原**——把旧局还原回去会覆盖新局。
[试玩] 开局成功时同理：`new_model_puzzle` 返回 True 后**当场** `_med_abandon()`，
不等下一帧绘制（否则那一帧编辑器浮层会画在新局上面）。

### 8.6 与格子画布共用一套界面骨架（2026-10-25）

两个还原态编辑器功能近似（都是「在盘面上点格 / 点缝摆出还原态」），所以外观也
统一到同一层：`gui/editor_chrome.py` 只做**绘制**，不掺命中判定（热区仍留在各自
模块的 rect 字典里，测试不受影响）：

| 元素 | 共用函数 | 效果 |
| --- | --- | --- |
| 工具条矩形 | `bar_rect(gui, h, left=)` | 右下角悬浮、贴状态栏上沿 8px、同一条宽度算式（`left` = 让位左侧面板）|
| 条底与标题 | `shell(gui, rect, title)` | 半透明深色 + 圆角 8 + 条上方灰色小标题 |
| 按钮 | `btn(gui, rect, text, color)` | 同色板、同圆角 6、hover 统一 +25 |
| 左面板 | `panel_bg` / `section` | 同底色、同分节节奏（标题 + 细线） |

按钮顺序也定死了（从右往左）：**退出 / ▶ 试玩 / 清空 / 存样式（保存）**。
两个编辑器的「第 1 行」放输入与次要操作（画布：m/n/step 参数 + 名字 + 清捆绑；
搭积木：名字 + 撤销），「第 2 行」左侧放状态 / 提示、右侧放主操作——换编辑器时
手指记得住位置。

画布的 [▶ 试玩] 是 2026-10-25 新加的（原来只能存样式再退到首页点样式库）：
**存样式 → 当场按该名字开局**，与搭积木的[试玩]同语义。收摊要点：存完要
`_ann_build_backup = None` 再开局——走 `[退出]` 的还原路径会把刚开的新局盖回旧局。

### 8.7 方形晶格：引擎零改动，只加了一族（2026-10-25）

加正方形与等腰直角三角形时最担心的「会不会把引擎搞崩」没有发生——**引擎侧
一行没改**。原因是 `editor_geom` 的两族共享同一条不变式：*顶点坐标恒为整数、
朝向像恒为整数顶点*。于是 `poly_of` / `snap_candidates` / 组件判定 / 缝族秩
/ 存档整数锚点全部原样成立，只是把「60° 旋转」换成「90° 旋转」、把「30° 命名
粒度」换成「45°」。

实测（`test/_test_model_editor.py` 的 `t_square_lattice_build` /
`t_square_lattice_save_open`）：2×2 正方形 → 连通、12 条合法移动、过保存门；
再拿两块 `rt45` 同锚点拼出一个正方形 → 推出 `d135` 斜边族（直角三角的斜边只
能配斜边，见 §2.1）；保存落盘 `basis=[[1,0],[0,1]]`、6 块、`d135/h/v` 三族；
`new_model_puzzle` 开局后能真的滑，方向字母表照常派生（A/B/C…）。

新增/改动的函数都在 `engine/editor_geom.py`：`SQUARE_BASIS`、`LATTICES`、
`lattice_info` / `basis_of` / `lattice_of_basis`（按长度比+夹角认族，不吃浮点
噪声）、`rot90` / `mirror_sq`、`d4_images` / `images_of`；其余几何函数统一加
可选的 `basis=` 缺省三角基，老调用零改动。

**一处命名坑**：族的「镜像变换」不能叫 `_med_mirror` ——那是「F 键镜像」的既有
方法名，同名会把 F 键盖掉（一按就 TypeError）。实际叫 `_med_mirror_v` /
`_med_rot_v`（v = vertex）。

### 8.8 试玩链路（2026-10-25 修通）

`[▶ 试玩]` = **过保存门 → 存模型（热注册）→ `new_model_puzzle(name, 1)` → 就地
收摊**。四步里任何一步失败都不开局：门不过 → 提示差在哪；没名字 → 亮名字框；
同名已存在 → 要求再按一次（防误覆盖）；模型注册失败 → 保存失败、留在编辑器。

开局后这盘是**普通模型局**（`kind = 模型名`，练习模式），操作与「谜题 → 模型谜题
▸」里点开完全一样：点缝选组 → 按住滑块沿缝拖动（模型板型保留「箭头 + 两次
触控」）；**键盘移动（按派生字母键）与 F1 虚拟键盘也已对通用通道开放**——因为
方向字母从几何派生、盘盘不同，键位直接跟这张字母表走（而非写死的 W/A/S/D）。
单次触控角度猜缝仍关死（各板型缝族方向、屏幕落向不同，不做逐板型适配）。
`new_model_puzzle` 里 `control_mouse_kb` 保持 False 即为此故。方向字母由
`compat.direction_table` **从几何派生**（见 `几何引擎.md` 同名段落），玩家看不到
字母，只在状态栏读到「向下左移动 1 步」这类中文方向名。

### 8.9 自造谜题的模式与「改谜题」（2026-10-26）

> 触发：用户报「自造谜题不能竞速（次要），但**影响是無法進入創造模式**；不能
> 刪、改、查；著色/連鎖/宏定義/求解器/標記這些接口難以統一實現，寧可點鍵時
> 直說『自定義沒這個功能』」。

**模式：创造放开，竞速仍拒。** 拦截只剩 `timed`（`gui/speedrun.py`
`set_game_mode` + `new_model_puzzle` 各一处）：创造首页的两个子入口都**自建
局面**——「① 打乱状态设计 / 格子画布」各自有 `_is_model_kind()` 拒绝，「② 还原
态设计 → 搭积木」用编辑器自己的预览局——与当前盘面形态无关，所以带 `create`
进模型局没有任何丢信息风险。此前 `new_model_puzzle` 把 `timed`+`create` 一起退回
练习，等于让模型局永远进不了创造模式（真 bug）。竞速依旧拒：`export_map` 的方形
分支会把 24 种朝向压成 `#`，存下来的初始局面还原不回同一题，成绩无意义。

**五类接口主动关停（`GUI._model_blocked`，与 `_mi_blocked` 同范式）。** 判据
`_is_model_kind()`（形态键不在旧四形态里），不硬编码 `'shatter'`。关停清单与
理由：分组着色 / 悬停连锁（"相邻"按方形四邻、三角三邻、米字八向手写，模型板型
的缝族与朝向表 per-model，套用会给**错的**着色而不是没信息）；复原提示标记
（走 `find_best_window`，方形口径）；宏（录制/执行都是方形 h/v 缝隙语义，回放
对不上）；求解器（只有 square/triangle/mi 三套语义）。行为：点下去**值不变**，
状态栏给「自造谜题：X 暂不支持（…）」。宏与求解器在**执行入口**拦（
`_start_macro_execute` / `_start_macro_recording` / `_start_auto_solve` /
`_do_solve`），菜单、快捷键、HTTP 三条路共用同一闸门。

**「改谜题」＝把在玩的这局导进搭积木。** 入口：创造 → ② 还原态设计 →
**改当前盘面**（只在模型板型显示，`_ann_btn_blocks_current` →
`_med_open(seed_current=True)`）。与「搭积木（自由板型）」空盘新建并列。
导入规则（`_med_seed_from_model`）：

* `spec.orientations` 只存**标签**，偏移在 loader 闭包里 → 用公开钩子
  `spec.cell_polygon((0,0), label)` 拿平面顶点，再乘 `basis` 逆矩阵、除
  `pos_scale` 解回**整数格偏移**；除不尽就放弃（绝不四舍五入，半格会让整盘
  悄悄挪位）。
* 标签按 `形状:序号` 归并，序号集可带空洞（只存被用到的像）→ 每形状**压缩
  重排**，同时记「旧标签 → 新序号」，块才落得回原位；捆绑组重编号（0 不捆绑）。
* 晶格族从 `spec.basis` 认（`BoardSpec` 新增 `basis` / `pos_scale` 两个带默认值的
  字段，由 `model_loader._assemble` 填——晶格族自此随**板型数据**走，不再只藏在
  闭包里）。
* 导不进的情形（碎三角那种旋转 30°、pos_scale=3 的基；标签不是 `形状:序号`；
  重复键）→ **退回空盘并在同一条通知里说明**，不静默给残缺盘。碎三角与
  「打开模型…」的拒载口径一致（§8.5 已记）。

已知取舍：导入后 spec 的缝族由编辑器**从形状边方向重新推导**，不沿用模型文件里
的 `seams`——手写模型的缝族（如 shield 的 d120/d30/d60/h 四族）可能与编辑器推出来
的不同，存回去会得到一套"更宽"的缝。这是编辑器"板型由几何决定"的既有立场，
不额外做缝族搬运。

### 8.10 画风统一：模型板型的渲染参数缺省（2026-10-26）

> 触发：用户报「自造謎題和原先畫風不一致（理論上應該和碎三角完全一致）」。

**根因不在渲染代码分叉**——两者都走通用多边形通道（`_draw_polygon_board`）。
差别只在**板型渲染参数**：`models/shatter.json` 显式写了 `seam_width: 6`
`corner_radius: 3`（6px 缝带 + 圆角），而编辑器存出来的模型（`shield`、`222`…）
没写这两个字段 → 渲染器退回方形旧口径（`gap_width` + 圆角比例）→ 视觉上变成
「块贴块 + 一条黑细线」。实测两张开局截图对比：碎三角是缝带分离 + 圆角，
自造模型是一整片 + 细线。

**修法**：把碎三角那组值定为**模型板型缺省**，并让编辑器存盘时显式写出。

* `engine/model_loader.py`：`DEFAULT_SEAM_WIDTH = 6.0`、
  `DEFAULT_CORNER_RADIUS = 3.0`；`_assemble` 用
  `doc.get('seam_width', DEFAULT_SEAM_WIDTH)`（`corner_radius` 同理）。文件写了
  就仍以文件为准（碎三角的 6/3 不变，手写模型可用 8/4 之类）。
* `gui/model_editor.py` `_med_build_doc`：保存的模型 JSON 显式带这两个字段
  （文件自解释，不依赖 loader 缺省值将来怎么改）。
* 约束照旧：`corner_radius ≤ seam_width / 2`（圆角弧不许越过缝，否则密铺顶点
  戳出放射状尖刺；见 `renderer` 通用通道的注释）。

回归：`test/_test_model_style.py`（A 缺省 6/3、B 显式值优先、C 编辑器存盘带字段、
D 渲染分支与绘制无异常）。

### 8.11 菜单悬停预览：复原态 + 一种打乱态缩图（2026-10-26）

> 触发：用户提「查的话……能不能每个謎題在菜單欄選擇的時候懸停就有提示，
> 顯示它的復原態和一種打亂態？」

模型板型的块形状由 JSON 决定，菜单里那行「shield（28 块）」看不出这题长什么样，
所以给一张图。实现独立成 `gui/model_preview.py`（**不碰 pygame.display、不改
任何 GUI 状态**），渲染侧只在 `draw_puzzle_sub_menu` 末尾挂一个
`_draw_model_hover_preview`。

**取形走公开钩子，不碰闭包**：`spec.cell_polygon(point, orient)` 给出该块的平面
多边形，与通用渲染通道（`SpecPolygonView.unit_polygon`）**同一数据源**，所以缩图
里的块形状与接缝走向与真盘一致。

**打乱态用真引擎**：`create_adapter_puzzle` + `game.shuffle(attempts, step,
bias=0, min_score=None, record=[])`，再取 `game.board.blocks` 的当前位置。随手
「把块乱挪」会画出这题**走不到**的局面，预览就成了骗人。`attempts` 取 GUI 口径
（`m*n*10 = 160`）的 1/4：160 步与 40 步在 104px 上看起来一样散，但实测
`models/222` 160 步要 625ms、40 步 ~160ms。难度门槛（`min_score`）整段跳过。

**两张图长得太像的坑**：合法滑动**不改变整盘轮廓**，单色画出来复原态与打乱态
几乎一模一样（实测肉眼难分）。故按**块序**给青→紫的色相渐变
（`_block_color`）：打乱 = 同一批颜色散到别处，一眼可见。块序 = 块在
`board.blocks` 里的下标；实测该顺序与 `spec.goal_blocks` 逐项相同，且合法滑动
只改位置不改对象顺序 → 下标是跨状态的块身份。

**绘制用真盘同款两趟画法**：先全填、再全描 1px（缝色取 `colors['gap']`）。
逐块「填+描」会被后画那块的填色吃掉半条描边，100px 下就是每条边粗细不一。

**每张缩图各自适配包围盒**（`_fit`）：打乱后块会散开到 1.5–3 倍，共用比例尺会把
复原态压成中间一小坨。缩图要的是「看清这题长什么样」，不是比绝对大小。

**首算耗时与异步**：首算最坏 ~500ms（引擎里头一次懒建几何/邻接缓存，第二次 44ms）。
`request()` 把首算丢进后台 daemon 线程，本帧返回 `pending`（菜单画「预览生成中…」），
下一帧自然出现；`thumbs()` 是同一条路的同步版，留给测试。结果按
`(模型名, 尺寸, 配色)` 缓存；编辑器保存后 `model_registry.reload(name)` 旁必须
`model_preview.clear_cache()`，否则「改了形状、预览还是老样子」。

**失败不静默**：模型文件坏掉 / 打乱抛异常 → `(None, None)` + 原因存
`last_error(name)`，菜单画「预览不可用：<原因>」。不假装这题没有预览。

**版式**：两张 104px 并排 + 标签（复原态 / 打乱态），面板 232×160，放在二级菜单
右侧；右侧塞不下（`screen_w` 不够）翻到一级菜单左边，两级都塞不下贴右边缘。
一级菜单外框记在 `self.puzzle_menu_rect`（翻边定位用）。

回归：`test/_test_model_preview.py`（23 项：能算 / 几何同源含「没转置没拉伸」/
按序上色 / 缓存与异步 / 失败不静默 / 菜单接线含翻边 / 方形局护栏）。

## 九、已知风险

1. **坐标基不统一**：现有三套坐标并存（方形整数、米字半整数、碎三角各向异性
   scale-6）。模型文件自带 `basis`，加载器只认「整数格 + 一个 basis」，不再有第二套。
2. **朝向标签重映射**：`view.rotate` 若做成语义旋转，需要重映射全部朝向标签并重新
   校验；因此定为显示层变换。
3. **性能**：几何路径比整数键查表慢一个量级。加载后必须预计算邻接与缝线并缓存，
   不能每帧现算（旧教训：6×6 打乱 2777ms → 缓存后 26ms）。
4. **存档兼容**：缝族命名与线号口径一旦改动，旧档回放会错位，靠 `model.hash` 拦住。
5. **统计口径**：捆绑出来的形状在数学上是多个块（菱形 = 2 块），做可解率 / 上帝之数
   统计时要单独标注，不能与原版四谜题混算。
