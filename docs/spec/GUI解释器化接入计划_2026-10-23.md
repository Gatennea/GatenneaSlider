# GUI 解释器化接入计划（碎三角先行）

日期：2026-10-23 ｜ 目标：把「几何引擎」兑现成**解释器**

---

## 0. 先说人话

理想形态是这样的：

> 几何形态的**定义**就是源代码，几何引擎是**解释器**，跑起来的结果就是一个**能在 GUI 里直接玩的新谜题**。
> 设计新谜题**不该**需要跑很久的测试；定义合法，就应该能直接运行。
> 万一跑起来效果不对，结论只能是「**这份几何定义写得不够好**」，而不是「解释过程出错了」。

本文件把这个愿景落成可执行的分阶段计划，并明确**每一阶段的验收标准**与**已知边界**。

一句话总结现状（2026-10-24 更新）：
**「显卡」已经接上，碎三角在 GUI 里可渲染、可点、可玩、可存档；旧三形态仍走手画路径（双轨未合流）。**
按用户指示，计划完成后的终态是**删除三个专属 GUI 接入（替换，不是并存）**——S5 全套回归已通过（两次终裁，唯一稳定红是已文档化的 `_test_tri_gather` C3c），删除前置的功能层对账见 S6：通用通道已覆盖游玩面（渲染/命中/选缝/拖拽/移动/撤销/求解/相机），还差功能层（编号字/捆绑组/指标标记/选块标记/方向箭头调用）与设计画布交互，以及一个产品级决策（引擎开关语义）。所以现在的定位不是"GUI 要大重构"，而是"给显示器接一根线，接完再拔掉旧那根"——S6 就是把 New 那根线补全到能独立承重，再拔旧线。

## 2. 方案：双轨增量（不重写 GUI，不碰既有回归）

旧三形态（`square` / `numbered` / `triangle` / `mi`）的渲染代码经过大量 GUI 回归验证（设计态、点缝捆绑、分组渲染、Undo 重放…），**重写等于自我引爆**。

因此采用双轨：

- **老轨道**：旧三形态继续走现有手画路径，一行不动 → 零回归风险。
- **新轨道**：凡 `BoardSpec` 提供了 `cell_polygon` 的形态（当前 = 碎三角），自动走**通用多边形渲染通道**。

判定分支用「**有没有数据**」而不是「**是哪个形态**」来分：

```
spec.cell_polygon is not None  →  通用渲染（任何形态都吃）
否则                          →  既有手画路径
```

这条判据本身就是"解释器"思想的落地：**按能力分派，不按名字分派。**

### S2 — 命中 / 点选  ✅ **已完成 2026-10-24（接触边界模型，就地修订过一次）**
**目标**：鼠标能点中块、能点中缝。

> **就地修订（2026-10-24，原文前提不成立）**：本阶段原文写「点缝复用适配器既有的 `all_gaps` + `is_valid_gap`（形态无关，无需新写）」。实测该前提**不成立**：碎三角还原态 `all_gaps()` 给出 **390 个候选**，而几何上真实的「跨分区接触边界」只有 **121 条**（L_v/L_d30/L_d150 各 16、G_h 17、G_d60/G_d120 各 28）——旧枚举口径把大量切不进滑块内部的代数线也报了，点击命中会大面积落空。故 S2 实际落地的是**接触边界模型**（`gui/board_view.py` 缝几何内核 + `adapter.is_live_gap`），不是复用 `all_gaps`。

**接触边界模型（实际做法）**：
- **候选缝** = 各族相邻 rank 边界（`distinct[1:]`），不枚举代数线；
- **缝的几何足迹** = 跨分区接触边（两多边形恰有 2 个公共顶点 ⇒ 共边，**必须容差匹配 1e-6**，精确 float 相等只数出 34/66）；
- **命中** = 点击到接触边的点段距离，排序键 `(距离, 族序, 线号)`；
- **活缝过滤** = `is_live_gap` 逐缝校验（两侧都推得动才算）；
- **歧义** = 活验 + 族序决胜。

**实测数据（2026-10-24，碎三角还原态）**：候选合计 **121**；容差匹配共边 **66** 条 = 引擎显式邻接表 66 条（集合相等）、空足迹 0；`legal_moves(1)` = **60** = 15 活缝 × 2 侧 × 2 向；活缝 = L_v{6,7,10,13,14}、L_d30{45,47,49,55,61}、L_d150{-27,-25,-23,-17,-11}，绿底三族恒死（无整周期滑动向量）；每条接触边被 1/2/3/4 个活缝共享（24 条独占）→ 点缝确有歧义，靠决胜键收敛；12 条边不被任何活缝覆盖 → 点击提示「选不动」。
**验收**：点任一块能选中、点每条合法缝能选中预期那一侧分量——PASS（`_test_polygon_view` / `_test_poly_render` / `_test_shatter_gui` S3 单步命令回路：`select_gap L_v 5` → opt → move → Undo 全绿）。

## 修订 R1（2026-10-24 傍晚）：S2「缝的几何」整段作废并重写

**作废的断言**（上文 S2 原文）：
- 「候选缝 = 各族相邻 rank 边界（distinct[1:]），复用 all_gaps」——逐整数 t 枚举会把**线穿过块内部**的 t 也算成缝，画到盘面上就是**锯齿缝**；
- 「缝的几何足跡 = 跨分区接触边」——前半句对（足跡确实沿块边），但当时没有做**「整条线必须全程贴边」**的过滤，于是"局部贴边、别处劈块"的线被当成缝；
- 「绿底三族恒 inert（无整周期滑动向量）」——**前提本身是错的**，见下。

**真实约束（为什么当年只能锯齿）**：`Lattice.neighbors_of` 的显式邻接按「折叠到基本域残差」查邻居。按**一个边长**平移后，34–38 块落到 24 个残差类之外 → 查不到邻居 → 整侧被判孤立 → 移动一律被拒。于是被迫用「整周期当步长」（沿这些方向高达 6 个边长 = 整个盘面高），为了凑出非零步长又把缝轴配错 30° → 锯齿。

**重写后的口径**（以代码为准）：
| 项 | 旧 | 新 |
|---|---|---|
| 缝的定义 | rank 半平面的代数边界 | **一条沿真实块边的直线**（整条线不得劈开任何块） |
| 候选缝来源 | 逐整数 t 枚举 | `BoardSpec.seam_lines(board, fam)` 几何给线（12 条） |
| 步长 | 整周期向量（2 个单元） | **沿缝一个边长**（30/90/150 → 1；0/60/120 → √3） |
| 连通性 | 查表残差邻接 | `BoardSpec.components` 几何共边（与残差无关） |
| 缝族命名 | `L_v/L_d30/L_d150/G_h/G_d60/G_d120`（名实不符） | `h/d30/d60/v/d120/d150`（**按线的方向**命名） |

**验收**：还原态 12 条真缝、48 个合法移动（12×2 侧×2 向）、足跡共线偏差 2e-14 px、途中位置零重叠、48/48 精确可逆。回归落在 `test/_test_shatter.py`（A1/A2/A3 三条公理）与 `test/_test_shatter_gui.py`（六族全可玩 + 劈块线被拒）。

**教训**：拿同一套模型生成结果再拿它验证结果 = 自证循环；「自洽」不等于「正确」。凡涉及"这条缝能不能滑"，必须问**物理**（直线 + 途中不碰撞），不能只问**引擎判据**。
