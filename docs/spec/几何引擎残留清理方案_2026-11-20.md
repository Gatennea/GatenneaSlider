# 幾何引擎殘留清理方案（碎三角為例）

> 記錄日期：2026-11-20
> 性質：規劃，未改代碼。触发：用戶「任何靠幾何模型定義的謎題都不該新增 Python 適配代碼，
> 殘留應全部清除」；trae 已發現同一批殘留。方案經主目錄只讀核對代碼後寫成。
>
> **一句話結論**：用户可以要的「全清」是**清掉界面與注册表的板型名依賴**，
> 不是「删掉所有 shatter 字符串」。有兩類**必须保留**，误删会出事——见 §1。

## 1. 先劃邊界：哪些不能清（否則一刀切會壞）

| 保留項 | 位置 | 為什麼不能删 |
|---|---|---|
| 生成器用的 Python 版 `shatter_spec()` | `engine/shatter_geometry.py:529`，唯一真使用者 `experiments/script__gen_model_shatter.py:31/61/137` | 生成 json 必須先有 Python 定義（先有雞再有蛋）；删了就無法再生成/校驗模型文件 |
| 差分測試的幾何 helper | `_test_shatter.py:47`、`_test_geometry_ops.py:21`、`_test_model_loader.py:22` 等 | 它們是「Python 版 vs json 版對拍」的基準，不是板型定義；删了就失去正確性對照 |
| shatter 方向字母表註冊 | `engine/compat.py:41/454-455` | **存檔兼容錨點**：歷史動作 dict 存的就是字母（`direction='d'`）。模型板型雖有確定性派生規則，但對 shatter 會給出與歷史表不同的字母；删註冊＝舊檔回放錯位 |
| 幾何算法鉤子的通用实现 | `engine/model_loader.py:393-446`（components / seam_lines / cell_polygon / overlap） | json 只描述形狀，不描述算法；這些由 loader 統一掛載，正是「收斂到一處」的目標本身 |

所以方案裡「全清」的準確含義是：**形狀 / 鄰接 / 還原口徑全進 json；行為鉤子只在 loader 一份；
界面與注册表不出現具體板型名**。保留的是「生成器的 Python 參考定義」與「存檔兼容錨點」，
兩者都不是「适应能力缺失」，而是工程上必要的冗餘。

## 2. 三塊殘留與清理動作

### 2.1 registry 文件頭的兩套敘事（最先做，純文檔零風險）

`engine/registry.py` 現狀：`:4` 寫「定義新謎題 = 寫一個 BoardSpec 並 register_board_type」，
`:18/22` 仍把 shatter 列在「當前 preset」；但 `:409-412` 明說「不再硬編碼、改由 json 註冊、
同一盤型只能一個來源」。讀到前面的人會以為該寫 Python 適配，正好與初衷相反。

改法（局部改，不重寫頭）：
- `:4` 改為**雙路徑**：內置板型 = BoardSpec + register_board_type（square/cubic/mi/tri 四個仍如此，
  `:405-408` 與 `:144-146` 準確）；模型板型 = 寫 `models/*.json`，由 `:421-423` 的 `_install_models()` 註冊。
- `:18/22` 的 shatter / shatter_lattice 兩條**刪除**，換一行指針「模型板型由 models/*.json 註冊，見 §409-412」。
- `:35` `from .shatter_geometry import shatter_spec` 是**死導入**（全倉除註釋外只剩本行），删。
- `:24-28`（tri 的 solved_check、KeyError 紀律）與 `:409-412` 保留，精簡重複措辭。

驗收：文件頭不再把 shatter 當 preset；`doclink` / `static_lint` 無新增。

### 2.2 界面層的板型名判斷（主體，按能力判據替換）

逐處核過（`gui/`、`GUI.py`、`puzzle_types.py`、`history.py`、`gui/session.py` 共約 29 處）：

- **A 類 17 處是純註釋 / 文案 / 舊方法名**（如 `records_panel.py:86/597/661`、`file_ops.py:827`、
  `GUI.py:1537-1538/1688`、`speedrun.py:81`、`puzzle_types.py:11/13/45/62`、`history.py:396`、
  `session.py:581`）。改措辭即可，零行為風險。
- **B 類 8 處已是或可改能力判據**：`records_panel.py:79 _rp_is_shatter` 實為「按 key 尾非尺寸識別模型局」
  → 改名 `_rp_is_model` 並同步 3 處呼叫；`:596/659` 的模型局攔截改查 `spec.cell_polygon` / `lattice.basis`；
  `file_ops.py:833/838/887` 的 `shatter = is_model` 改名並統一走 `_is_model_kind()`；
  `events.py:1124/1198` 兩個 `elif kind=='shatter'` 分支與緊隨的通用 `new_model_puzzle(kind, ps)` **等價，直接删分支**。
- **C 類 4 處需保留具體身份，但用模型名/hash 而非寫死**：`file_ops.py:908` 存檔要寫 `puzzle.type=kind_now`
  + model hash（改 `if is_model`，kind_now 仍取真實名）；`GUI.py:1539` 舊轉發入口
  `new_shatter_puzzle → new_model_puzzle('shatter')`——遷走呼叫方後删方法；
  `events.py:1128/1202` 隨 B 的分支合併自然消失。

可複用的現成能力判據（**別另寫一套**）：
`GUI._is_model_kind()`（`gui/session.py:577`）、`kind not in _NATIVE_KINDS`（`puzzle_types.py:24`）、
`len(spec.seam_families)`、`spec.lattice.adjacency is not None`（`engine/lattice.py:74`）、
`spec.solved_check is not None`（精確拼合，`engine/model_loader.py:412-418`）、
`model_registry.loaded(name)`（`engine/model_registry.py:111`，含 spec/title/disabled_seams/hash）。

驗收：全倉 `grep -rn shatter --include='*.py'` 去掉「保留項」後為 0；
相關護欄（`_test_shatter*`、`_test_engine_gui`、`_test_model_loader`）全綠。

### 2.3 行為鉤子收斂（邊界已成立，只做清點）

`BoardSpec` 的鉤子（`engine/board.py:301-306`）：`seam_clear / solved_check / overlap /
cell_polygon / components / seam_lines`。json 已能聲明 basis、pos_scale、orientations、tiles、
seams、`solved:'exact'` → solved_check、縫寬/圓角/view（`model_loader.py:412-445`）；
算法类（components / seam_lines / cell_polygon / overlap）由 loader 統一掛載。

- `shatter_geometry.py:385 _solved_check` 與 loader 的 exact 版逐字等價、**無外部呼叫者**，
  但它是 Python 參考版的組成部分，隨生成器保留（見 §1）。
- `engine/compat.py:450-453` 註釋過時：稱由 `_test_shatter` 的雙射斷言釘死，但該斷言不存在；
  真正相關的是 `_test_shatter_gui.py:90-91`。改註釋，不改邏輯。
- 可選增強（**不屬清理、另立項**）：把方向字母表寫進 json schema，由 loader 註冊，
  讓 compat 的 shatter 特例也能消失——但要先保證舊檔回放字母不變，風險高，別塞進本次。

### 2.4 「死編號」是症状，已修，作為驗收樣板

提交 `e97eadf`（dev 分支）自承「碎三角編號從未顯示，手動賦號驗證 0→3067 黑像素」：
通用繪製通道照搬方形編號語義，編號字畫在填色趟之前被整塊蓋掉，而碎三角入口不開 numbered，
所以長期無人發現。這正是「兩套定義在繪製層撞上、沒人對齊」的症狀。該提交已修
（抽 `draw_block_number`、收集落地表挪到三趟後、40/40 護欄），已合進 main。
清理時以它為樣板：**凡通用通道裡假設某形態一定有的語義，都要能對「沒有該語義」的板型降级**。

## 3. 執行順序與分工建議

1. **步 1（純文檔）**：registry 文件頭 + compat 過時註釋 + A 類 17 處措辭。零風險，可與其他工作並行。
2. **步 2（行為等價重構）**：B 類 8 處改能力判據、删兩個等價菜單分支；C 類 4 處改真實模型名/hash。
   必須逐處確認語義，不可機械替換。
3. **步 3（清點與死導入）**：删 registry:35 死導入、`_test_polygon_view.py:31`、
   `script__chk_s2a_kernel.py:19/58-60`（後者 `__import__` 代碼版 `_reduce_shatter` 查鄰接，已不適用 loader 版）；
   `_test_model_registry.py:69-71` 改為直接與 json 比（其 `:60-67` 已這麼做）。
4. **步 4（驗收）**：全倉字符串計數 + 三套護欄 + `static_lint --strict` + `doclink --strict`。

步 2/3 都動 `file_ops.py` / `events.py` / 測試，與其他 AI 工作交疊，**建議同一 AI 串行做完**；
步 1 可先派一個 AI 並行。验收必须跑真实行為測試，不接受「grep 源碼沒有某詞」当判據
（項目記過的假判據）。

## 4. 不做的邊界

- 不删生成器 / 差分測試的 Python 幾何定義（§1）。
- 不為「消滅 compat 特例」改 direction_vocab 机制（舊檔兼容風險，另立項）。
- 不改 json schema（除非另立方向字母表增強項）。
- 不碰三維 / 其它形態的幾何定義，本次只清「碎三角作為 Python 板型」的殘留。
