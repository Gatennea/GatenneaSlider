# 打包與發版

> 2026-11-06 從 `agents.md` §4 / §19 拆出（內容未改，另補一條開機動畫資源的打包約定）。
> 相關：`Gatenneaslider.spec`、`build_exe.bat`、`build_release.py`、`gui/updater.py`。

## 1. 打包鐵律

- 每幀調用的可選功能**必須能力檢測**（主循環一個大 try 包住事件 + 全部繪製 + flip）；
  任何異常只讓整幀不繪製（白屏但進程活着、windowed 無輸出）。
- 新增運行時資源**必須同步 spec 的 `datas`**，不可排除 `pygame.cursors` / `pygame.sprite` / `pygame.mask`。
- 日誌路徑順序：exe 同級 `config/` → `%APPDATA%/GatenneaSlider/` → temp。
- **開機動畫 / 啟動圖**：幀序列走 `datas`（`assets/picture/boot/frame_*.png`），啟動圖走
  `EXE(splash='assets/picture/splash.bmp')`（PyInstaller 在 exe 啟動段自行顯示，GUI 起來後
  `pyi_splash.close()`）。兩者都屬可選功能——加載失敗只跳過，不許崩。
- 新增 `datas` 後**必須實測一次打包產物**：源碼能跑 ≠ 打包能跑（`_MEIPASS` 路徑、缺檔、白屏都在這一步暴露）。

## 2. 版本號與發版（2026-10-17 改）

- **版本號 = 打包日期 `vYYYYMMDD`**（`build_release.py` 不再用 Git 提交數）。不給 `--version` 時自動取今天。
- **改因**：舊規則「Git 提交數 + 日期」的提交數會被 **squash 合併壓小**，提交數不再單調，曾發生
  `v154 < v197` 倒退——發出去會讓裝 v197 的用戶被更新器判為「已最新」、**永不彈升級**。
  日期天然單調、與 git 歷史無關。
- **更新器兼容**：`gui/updater.py` 只比較版本號 v 後第一個 `-` 前的整數（`v20261017` → 20261017），
  恒大於舊的 `v197` 等提交數版本，**過渡無礙，比較邏輯不用改**。
- **手填版本號約束**（`build_release.py` 校驗）：須 `vYYYYMMDD` 或 `vYYYYMMDD-xxx`，且日期**不早於今天**
  （防倒退）；舊制 `vN-YYYYMMDD` 放行。
- **同日發兩版**：直接取下一天日期，或 `--version vYYYYMMDDHHMM`（帶時分才能真正比舊的大；
  `v20261017-2` 這類後綴比較時只看前導整數 20261017，同日不會判新）。
- **發版走 GitHub 網頁手動**：tag 填版本號，上傳 **`GatenneaSlider-Windows.zip` + `version.json`**
  兩附件；zip 文件名必須固定（下載鏈接 / 更新器都依賴它，改名即失效）。
