# 自由捆绑模式（Bandaged Mode）设计

> 移植对象：捆绑魔方（Bandaged Cube，Uwe Meffert 1980s）——把相邻块粘成
> 刚性整体，切得过层的转动被迫变成「宽转动」，合法移动变少；打乱只用合法
> 移动，故天然保证有解（Bicube 上帝之数 28）。

## 核心映射

| 捆绑魔方 | 本游戏对应 |
|---|---|
| 粘住的块（glued block） | 捆绑组（group）：若干个块的刚性整体 |
| 层切线切不过粘块 | 缝隙（分割线）切不开捆绑组 |
| 宽转动（Uw：整片被带着走） | 组内任一块被选中 → 整组一起平移 |
| 合法移动变少 | 选中/移动判定天然拒绝切开组的走法 |
| 只用合法移动打乱 → 有解 | 安全打乱可逆校验在捆绑态自动继承 |

关键性质：**捆绑态合法移动 ⊆ 原游戏合法移动**（限制型改动），因此
- 可逆性 ⟺ 有解 的既有定理不变（子集内仍成立）；
- 死局分析不变（死局集合只可能更早到达，不会新增）；
- 求解器/heuristic 不变（它们本来就按单块位置工作，捆绑只改选中语义）。

## 语义细则

1. **捆绑组是刚体**：组内块永远相对静止；任何使组内任一块进入选中片的
   操作，都会把整组拖入选中片（即使组员在盘面远处）。
2. **平移整体性**：`try_move_ex` 逐步验证碰撞 + 单一连通——组被拉扯时
   若与未选中块碰撞则整步拒绝（这就是捆绑魔方「这面转不动」的体感）。
3. **判胜不变**：位置对了组内自然对（捆绑不改目标态定义）。
4. **打乱**：在捆绑态下运行，`opt` 天然遵守捆绑 → 安全打乱的可逆校验
   自动收窄到捆绑态合法移动，终态仍保证有解。
5. **形态**：三形态通用（v4 起）。差异只在坐标——方形 `(r,c)`、三角
   `(i,j,up)`、米字 `(r,c,q)`（r/c 可为半整数）；邻接与缝的换算由各形态
   自己的 `neighbors_of` / `seam_between_positions` 提供，规则层
   （`bandage.py`）不含任何形态判断。**刚体语义唯一实现点 = opt 末尾的
   `_expand_opted_groups()`**：把选中片里出现的组整组拖入，碰撞/断连交给
   既有 `try_move_ex`/`_check_step` 拒绝 ⇒ 绑定态合法移动 ⊆ 原游戏。
   切勿把刚体语义下沉到 `try_move_ex`（会绕开 opt 的选中语义，撤销/打乱/
   求解器全要跟着改）。

## 交互（v2 已落地：设计还原态）

> v1 原案「游戏内快捷键 B 路径捆绑」未采用。2026-10-20 用户定向后
> 落地为「设计」入口，并把**还原态与打乱态的语义分开**：

- **入口分离**：
  - 创造模式首页 [随机生成] / [手动构造] —— 造**打乱局面**（当前谜题）；
  - 谜题菜单 **「高级选项...」**（`_ann_open_advanced`）—— 造**还原态
    样式**（形状 + 捆绑），产品是样式文件而非局面。首页原 [设计还原态]
    按钮已移除，避免和「造打乱局面」混淆；
  - 首页 [样式库▾]（方形创造模式） / 谜题菜单的自定义预设 —— 选已存
    样式直接开局（样式 = 还原目标）。
- **设计画布**：初始 = 进入前那盘棋（盘面 + 捆绑原样带入）。点格增删
  滑块拼出想要的形状；点缝绑解（见下）。
- **点缝绑解**（2026-10-20 定案，取代「点两块 + BFS 最短路径」）：
  - 点缝两侧**不同组/未绑** → 把两侧（含各自整组）并成一组；
  - 点捆绑块**内部缝** → 沿整条缝解绑，把跨该缝的组拆成两半（贯穿整块，
    解剩 1 颗的组直接删 = 单块无捆绑）；
  - 命中判定的顺序是**先判缝再判格**：缝只有 4px，`get_cell_at_pos` 在缝
    上也会返回相邻格，先判格会把绑/解误当增删滑块。
- **存样式**：命名后存 `config/design_styles/<名>.json`
  （cells + groups + 尺寸）。保存前**三道拦截**：非空盘面 + **连通性**
  （整片形状连通、每个捆绑组各自连通，见 v4）+ **「可打乱」判定**
  （至少 2 颗各自能滑、且这两颗边相邻；`has_legal_move` 那种整体冻形
  自然被它拦下）。
- **样式开局**：按 `kind` 分派建局后 `apply_pattern(cells, groups)` +
  `set_goal_pattern(cells)`。方形还原判定走 **D4 八变换 canonicalize
  （旋转/翻面都算还原）**；三角/米字见到 goal_pattern 改为「位置集合与
  样式逐块相同」。状态栏常显「样式：X」。
- **视觉**：同组滑块画成**一整块**（组内缝隙填平、只描组外轮廓），沿用
  现有块色/边框色，**不引入新颜色**。方形走 `draw_group_chunks`（矩形
  拼块 + 桥接），异形走 `draw_group_pieces`（逐块填色 + 组内填缝四边形
  + 只描非共用边）。「≥3 块共用顶点」补同色圆点有条件：该顶点的**内角
  和必须 = 2π**（真的在组内部才补；180° 的顶点在组外边界上，补了会溢
  到组外形成一个凸起——2026-10-21 用户截图发现的坑）。
- 捆绑态下「指示/自动求解」禁用（求解器按无捆绑假设工作，答案会错）——
  HUD 明示原因。

## 存档/撤销

- `Block.group`（int，0=无组）随快照进 history；撤销/重做/压缩存档
  （重放式）都恢复捆绑状态。
- 落盘统一「坐标各分量 + gid」`[[..., gid], ...]`（`history.groups_to_json`）：
  方形旧档的 `[r, c, gid]` 天然兼容，三角多一个 up、米字多一个 q（还可能是
  半整数），天然通吃。空组不写字段（无捆绑局存档与旧版逐字节同形）；
  `_state_hash` 只在存在 groups 时计入 → 旧压缩档哈希不变。
- 新谜题（new_puzzle / 载入）重置为无捆绑；打乱保留当前捆绑。

## 分阶段

- **v1（已落地，`a7f1a7c`）**：引擎层（Block.group + opt 捆绑扩展 +
  捆绑/解绑 API + goal_pattern/pattern_fit + has_legal_move 冻形检测）
  + history 快照 + 差分测试（opt/try_move 与旧版在无捆绑时逐字一致）。
- **v2（已落地，`e3bb05e`）**：GUI 设计态（捆绑/解绑/样式存取/样式开局）。
- **v3（2026-10-20）**：设计独立入口——[设计还原态] 与 [手动构造] 分开
  （还原态 vs 打乱态语义分离），首页 [样式库] 开局；随后入口迁到谜题菜单
  「高级选项...」，绑解改为点缝。
- **v4（2026-10-20，本版）**：三角 / 米字捆绑扩展。
  - 引擎：`bandage.py` 提供形态无关的组簿记 + `BandageMixin`
    （`neighbors_of` / `seam_between_positions` 两个钩子），三角/米字的
    `opt()` 末尾调 `_expand_opted_groups()` —— **刚体语义只有一个实现点**，
    方形 `game.py` 一行未动；
  - 缝反推：`seam_between(a, b, valid)` 用各族 `gap_rank` + `side_of` 复核，
    米字必须再用 `is_valid_gap` 过滤（同格 N/E 会被 'h' 误判）；
  - 存档：位置变长编码（见上）；
  - 渲染：`gui.group_render.draw_group_pieces`（逐块填色 + 组内缝铺同色
    四边形 + 只描非共用边；≥3 块共用顶点按**内角和是否 2π** 判断要不要
    补同色圆点——180° 的顶点在组外边界上，补了会溢出成凸起）；
  - 交互：点内部缝 = 点中该组滑块（三形态统一）；
  - 设计态：**还原态形状三形态都可自定义**（点格增删 + 点缝绑解），
    样式落 version 2（带 `kind`），按样式开局 = 按 cells 摆形 + 捆绑 +
    `set_goal_pattern`（三角/米字的 `is_solved` 见到 goal_pattern 就改为
    「位置集合与样式逐块相同」；安全打乱路径可逆，精确比对不会判不出）；
  - **连通性判定（用户明确要求）**：存样式前必过
    `_ann_validate_connected` —— ①整片形状必须连通（两块互不相连的滑块
    在「每步后单一连通」规则下永远滑不到一起）；②每个捆绑组各自连通
    （刚体组断开的话整组一起动换不出合法走法）。相邻关系问形态自己的
    `neighbors_of`（三角 3-邻接、米字 5-邻接）。
  - 未做（下一批）：样式载入画布再编辑、关卡预设捆绑。
