# 求解器 AI 搜索优化方向（启发式最优解家族）

## 0. 一段说明：为什么单独成篇

`docs/solver/` 下已有两份相关文档，但**不覆盖本篇内容**，分工如下，避免新对话重复：

| 文档 | 家族 | 性质 |
| --- | --- | --- |
| `求解器優化發現.md` | profiling 驱动的实现优化 | 位棋盘、剖面缺陷预筛、阶段 0–4，把现有贪心跑快 |
| `異形求解器計劃.md` | tri/mi 聚拢求解器移植 | 照搬梯度骨架，聚拢度直接移植 |
| **本篇** | **启发式搜索 / 最优解** | 用可采纳启发（PDB + A*/IDA*）从「给一个解」升级到「有下界剪枝 / 最短解」 |

本篇与上面两份**互补不冲突**：上面两份是「现有管线提速」，本篇是「换更强的搜索范式」。

> 補註 2026-11-10：上表是 2026-10-15 的分工，不代表這些方向「可做」。本篇自述為「原始建議」，勿當驗收結論；`docs/solver/求解器優化方向_可行性判據.md` 第 3 節逐條列出本文各提議的前提與出局判據。

## 1. 当前方形求解管线的成本基线（讨论起点）

来自 `求解器優化發現.md` 的实测：

- 聚拢（gather）：**30.6 ms/步**
- 填洞（gap-fill）段
- GBFS（贪心）：**1204 ms/步** ≈ 聚拢成本的 **~40 倍**
- 现状：GBFS 贪心、给**一个**解但**不保证最短**；搜索成本集中在那一步。
- `auto_solve` 已按**空位数路由**（≥3 空位走「补缺宏」先行），这是现成的算法路由骨架。

## 2. 四个实打实的改进方向（A 段原文精炼）

### 2.1 Pattern Database（模式数据库）做启发式剪枝
- 把若干块的相对位置**预计算成精确距离表**，作为 **admissible heuristic** 喂给 A*/IDA*。
- 这是 Korf 解 15-puzzle 的标准做法，能把「贪心碰运气」变成「有下界剪枝」。
- 直接压低那 1204 ms/步 的搜索成本（用下界砍掉无望分支）。
- 对应 `求解器優化發現.md` 的「阶段 4 建表」方向。

> 補註 2026-11-10：PDB 需要全量建表，只有能全量枚舉的小尺寸做得動。`experiments/script_quantify_gap_optimality.py` 預研量到無表解長中位 3.7×、最差 6.8×，但 `docs/agent/待办清单.md:689-694` 記「是否投入建表（研究量級）待用戶拍板」。**這不是邏輯上沒用，是成本與覆蓋問題**；別寫成「順手白撿」，也別對玩家大尺寸許諾效果。

### 2.2 升级到 IDA* + 可采纳启发，追求最短解（上帝之数方向）
- 当前是「一个解」，**不是最短**。
- 配合 2.1 的 PDB，可逼近数学已得的上帝之数：
  - **(4,4,2) 回程上帝之数 = 17（正向 23）**
  - **(4,4,3) 回程上帝之数 = 29（正向未测）**
- 这些数学上界（见 `docs/math/` 系列）可直接当**对照真值 / 限深上界**使用。
- 研究价值高，但比 GBFS **慢**（最优解 vs 可行解 的固有代价）。

> 補註 2026-11-10：「可直接當對照真值／限深上界」**只適用上面兩檔有全量表的尺寸**；`docs/math/遊戲衍生的數學問題.md:76` 原話「其他的看数据库，或者自己用建表脚本来算」。靠估算／擬合得出下界的版本已否決（見開頭前提 3）。另外 `solver/ida_star.py` 已有完整實作但已沉底、啟發非可採納、fast_mode 不保證最優；別把「升級到 IDA\*」當成從零開始的新點子。

### 2.3 异形（tri/mi）搜索补强（阶段 4 待实测）
- tri/mi 可达放置只有「1 朝向 × 全部平移」（tri 已实证无 120° 对称；mi 合法偏移 = 类自同构余数对 ∧ 奇偶一致）。
- 搜索空间结构不同，当前处理偏弱。
- 先做异形**建表 / 搜索实测跑通、量化差距**，再决定启发式怎么适配异形（异形没有轴对齐行列，PDB 的「块相对位置」定义要重新设计）。
- 详见 `異形求解器計劃.md` 的 M5（建表试点，tri k=4 step=2 先行）。

### 2.4 自适应回落 / 多算法路由
- 现有 `auto_solve` 已按空位路由（≥3 走补缺宏），可扩展成：
  - GBFS 卡住 → 切 IDA*；
  - 或按 Φ（剖面缺陷）动态选算法。
- 这是把所有算法**编排起来**的层，不是新算法本身。

> 補註 2026-11-10：「AI 在線仲裁／介入時機」已否決（確定性可檢測，不需 AI，`docs/agent/转交文档_API改进与求解器AI结合.md:88,120-122`）；但「把 `gap_first = len(holes) >= 3` 這類寫死的路由判據抽成可注入參數」仍然成立且風險低，見 `docs/solver/求解器優化方向_可行性判據.md` D1。兩者別混為一談。

## 3. 新对话建议切入点

1. **先量差距**：用 (4,4,2) / (4,4,3) 的数学真值（回程上帝之数 17 / 29（4,4,2 正向 23）、死局结构）当标尺，量化当前 GBFS 给的解离最短差多少——确认「追求最短」是否真有玩家价值。
2. **PDB 预研**：先在 4×4 级（小状态空间）试建一块 PDB，验证 admissible heuristic 能砍掉多少 GBFS 分支。
3. **异形建表**（M5）：tri k=4 step=2 状态空间计数器先跑，量级可行再落地。
4. **路由层**：把 2.4 的「GBFS 卡住切 IDA*」作为最后一层兜底。

> 補註 2026-11-10：第 1 條的「死局結構」不該拿來當玩家標尺 —— 玩家開局必然可解，死局黑名單（2026-11-10 已整層移除）當年只覆 (4,4,2) 的 9 個態且永不命中（`docs/spec/設計訪談總結.md:267`）。第 4 條的 IDA\* 已沉底，先讀開頭前提 3。量差距本身仍值得做，正式設計見 `docs/solver/批量实验设计_盲区与解长.md`。

## 4. 可用的现成加速点（白捡，不属本篇但应优先回馈）

数学复现已得的回程上帝之数（17 / 29；4,4,2 正向 23）与死局结构（弱或必要条件、短边≤3 等），**求解器目前没用来做限深 / 死局剪枝**——这是独立于本篇「搜索范式升级」的低成本剪枝回馈，可在本篇落地后顺手接上。
