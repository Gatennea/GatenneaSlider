# 实验设计：混合流水线内「填洞宏」去留（fill-in-hybrid 消融刷新）

> 2026-10-16 用户观察 + 主张；先测试后决定。受众：求解器维护者。

## 1. 背景

用户 2026-10-16 指出：`auto_solve` 的「混合流水线」候选内部还含一层「填洞宏」，与 auto_solve 外面独立跑的「补缺宏」入口重叠——「颗粒度没对齐」，主张直接删掉混合里的填洞宏；但先测试验证「不删就是拖后腿」的猜想。

**代码事实**（`solver/hybrid_solver.py` alt 流水线）：

- 混合流水线 = 多段「聚拢小块 ↔ **填洞宏**（`fill_macro.solve_fill_macro`）」交替（≤8 轮）→ GBFS 兜底（≤12 轮）
- 外面独立候选 = `gap_solver.solve_gap_macro`（缺口求解器：外层封壳 + 内层复用 `fill_macro.solve_single_void`）——**两个不同模块、机制重叠**，不是同一行代码跑两遍

**既有实测（exp20，2026-09-30，提交 a4891bc）——猜想已被精确测过一次，结论相反**：

- `skip_fill=True`（= 聚拢 + GBFS、无填洞，正是提案配置）vs 先聚后填：5×5 step2 8 种子，7.5s → **12.7s（慢 69%）**，成功率均 100%
- 且「填洞+聚拢多段交替」这个设计本身就是用户 2026-09-30 的主张（提交信息：「实测用户主张」）
- exp20 自注教训③：单发聚拢度会抹掉填洞的贡献，**端到端时间是唯一裁判**

**但 exp20 有三个局限，补测有价值**：

1. 代码旧：消融用的 guided 是 exp11 的旧副本；当前 hybrid 已演进（canonicalize 去重、node_budget=80000、max_rounds=12、replay 锚定采纳）
2. 语料窄：仅 5×5 step2（8 种子）；4×4 有表仅参考
3. **层级不全**：只量了 `hybrid_solve` 单层，没量两个真实入口——

## 2. 删除提案的真正作用面：两个入口

| 入口 | 路径 | 外面有独立补缺宏？ | 删混合填洞的影响 |
|---|---|---|---|
| A「混合求解」 | `hybrid_solve_with_table`：先查表，没表走混合 | **无** | 直接全失，无补偿 |
| B「自动规划」 | `auto_solve`：查表 → 补缺宏/混合按空位数路由 → 全败择优 | **有** | 独立补缺宏可能补偿——**从未测过，决胜层** |

## 3. 实验问题

- Q1（L1 单层刷新）：当前代码，混合去掉填洞是否仍劣化？复测 +69% 是否成立
- Q2（L2a 入口A）：GUI「混合求解」删填洞的直接代价
- Q3（L2b 入口B 决胜）：「自动规划」删填洞，独立补缺宏是否补偿

## 4. 实现方式（零生产行为变化）

- `hybrid_solve` 加 `use_fill=True` 关键字（默认现行为；续算/直跑两个分支都生效）
- `auto_solve` 加 `hybrid_use_fill=True` 透传给 `run_hybrid`；`hybrid_solve_with_table` 经 `**kwargs` 自然透传
- 最终删/留依 Q3 定：删 → 把无填洞固化为唯一路径并清理；留 → 参数保留供将来消融

## 5. 语料与口径

- 只用无表尺寸（全库仅 `solver/data/4_4_2` 有表）：5×5 step2 / 5×5 step3 / 6×6 step2；`harness.gen_state` 可复现生成
- 冒烟：每尺寸 4 局；正式：每尺寸 12~16 局
- 指标：**端到端运算时间为主**（用户铁律：运算时间 > 解的长度），成功率、解长为次；逐局配对（同 seed 同局面 on/off）；报配对差值的中位与分布，不只均值
- 每局记录：结局、路由先后（由空位数定）、各阶段耗时、动作链长、终态 score/Φ
- 超时口径：L1 120s/局，L2 300s/局；timeout 单独一类，不混入失败
- 语料的空位数分布自然覆盖两种路由顺序（≤2 混合先行 / ≥3 补缺宏先行），无需专门构造

## 6. 测量纪律与跑法

- ABAB 交替 + 逐轮配对：每对 (seed, 尺寸) 先 on 后 off，下一对反转顺序，抵消机器热态/漂移
- 分块执行：每块 4~6 局、块间落盘 jsonl（躲避后台 10~15 分钟截断），断电不丢数据
- 后台跑，完成自动通知，不干等
- 脚本自审 + fixtures 冒烟后，交独立子代理客观复核（顺序效应/配对正确性/超时口径）

## 7. 产出

- `experiments/results/fillin/汇总.md`：三问各一张配对表 + 决策建议
- `rounds.jsonl`：逐局原始记录；失败/部分局按批量实验约定存「逐步快照」存档

## 8. 决策规则（先定后跑，避免骑墙）

- Q3 配对时间 off 中位 ≤ on +5%，且成功率不降、部分局终态聚拢度不降 → **删**
- Q3 off 慢 >10% 或成功率降 → **留**（exp20 结论更新为「当前代码仍成立」）
- 5%~10% 之间 → 看分布 + Q2 人工定
- Q1/Q2 为参考面：Q2 大概率复现劣化，正好量化「混合求解」菜单入口删填洞的代价
