# 三維聚攏求解器：基準與第一輪優化記錄（2026-11-20）

關聯：方案 `docs/agent/三维求解器_原版借鉴与公式生成器结论.md`（以下簡稱「方案」）。
本文件只記「量了什麼、改了什麼、實測多少」，不做完成度自述（狀態見 `docs/README.md`）。

## 1. 基準口徑（方案 P0 第 1 步）

`experiments/script__bench_cubic_gather.py`：

- 尺寸 3×3×3 / 4×4×4，各 8 個固定 seed；同 seed 必然生成同一打亂局面；
- 打亂：引擎安全打亂 120 / 200 步（step=1）；
- 求解參數固定：`max_steps=240, patience=80, max_wait_time=20, target_gather_score=None`；
- 記錄牆鐘（中位 / p95）、解出率、返回動作步數、展開節點數（`stats.expanded`）、失敗原因；
- 結果落盤：`experiments/results/cubic_gather_bench_<label>.json`。

復跑：

```bash
D:/python/python.exe experiments/script__bench_cubic_gather.py --label baseline --seeds 8
D:/python/python.exe experiments/script__bench_cubic_gather.py --label opt3 --seeds 8 --profile 1
D:/python/python.exe experiments/script__bench_cubic_gather.py --label step2 --sizes 3x3x3,4x4x4 --steps 2
D:/python/python.exe experiments/script__bench_cubic_gather.py --label k0 --sizes 3x3x3,4x4x4 --phi-k 0
```

`--steps` 收等級逗號列表；`--phi-k` 收預篩 top-k（0 = 關閉）；未登記尺寸的打亂力度
默認取「塊數 × 4」，已登記的 3×3×3 / 4×4×4 沿用 120 / 200 步以與歷史數據同一局面。

## 2. 基線剖析（4×4×4，cProfile，22.7s）

| 熱點 | 佔比 | 說明 |
|---|---|---|
| `_box_count` 4.4M 次 | ~36% | 每次調用跑 6 個 `min`/`max` builtin |
| `cubic_metrics` 累計 | ~49% | 每個候選都算一次完整 3D 指標 |
| 候選鏈（opt / try_move_ex / restore_state / `_rebuild_blocks`） | ~40% | 每個候選 `snapshot → opt → try_move → restore`，restore 重建全部 Block |

結論與方案 §1.4 的推測一致：指標層與候選回滾鏈各佔約四成，不是單點問題。

## 3. 本輪落地（全部在 `solver/ml/cubic_gather.py`）

1. **純座標候選展開**：`cubic_candidates()` 直接用引擎 `Board.legal_moves(step)`，
   落點 = `Move.moved + step·方向 ∪ 其餘`；候選評估不再改盤面，`restore_state`
   只保留「整輪失敗回滾」一次。
   - 同時補上方案 §2.1 的唯一真缺口：**逐連通分量枚舉**，動作帶三元 `rep_cell`；
     `_apply_cubic_action` 也改為優先按 `rep_cell` 定位塊（與 GUI 回放同口徑）。
   - 連通判據仍走板型自帶的 6 鄰接 lattice，不另造 3D bitboard（避免與引擎語義分叉）。
2. **`_box_count` 去 builtin**：6 個 `min`/`max` 改成純比較夾取，語義不變。
3. **指標層省調用**：當前態指標跨輪攜帶；選中候選的指標直接作為落點指標；
   step=1 跳過逐起點的 mod 餘數判定。
4. **Φ 預篩 + top-k**（方案 P1）：`_candidate_phi` 用 O(塊數) 的兩個量
   （當前最優窗口內塊數 / 貼合候選最小角同形窗口內塊數）排序，只對前
   `phi_prescreen_k=8` 個算完整 `cubic_metrics`；`k=0` 可關閉。
5. **實心盒快速還原判定**：`_solid_goal_signature` + `_solved_fast`；
   自訂 `goal_pattern`（非實心盒）回 None，仍走引擎 48 對稱 `is_solved()`。
6. **指標補鍵**：`cubic_metrics` 增加 `holes` / `outside`（方案 §2.3 第一步）。
   `protrusion` 需要目標形狀本身，本輪不給假數據。

## 4. 實測（同一固定打亂集）

| 尺寸 | 基線 中位 / p95 | 本輪 中位 / p95 | 中位倍數 |
|---|---|---|---|
| 3×3×3 | 6.30s / 11.39s | 0.776s / 1.845s | 8.1× |
| 4×4×4 | 20.20s / 20.37s | 4.396s / 7.757s | 4.6×（基線 8 局全部撞 20s 上限，真實倍數更大） |

誠實說明：

- **解出率仍是 0/16**，基線也是 0——單次聚攏不承諾還原，這不是本輪引入的退化；
  真正要解出需接方案 P1 的逐洞/單洞收口。
- 返回步數不可跨版本直接比較：基線被 20s 上限截斷，本輪同一時間預算內能走更多步。
- 展開節點數（本輪中位）：3×3×3 6528、4×4×4 14200；候選數已從舊近似枚舉的
  ~36 漲到完整空間（4×4×4 實測 144），速度提升是在**動作空間變大**的前提下取得的。

## 7. 參數矩陣（第二批「多試試」，2026-11-20 同日）

所有對照都在同一固定打亂集上跑（同 seed = 同局面），除注明外 `max_wait_time=20`。

### 7.1 Φ 預篩 k：k=8 在速度與終態兩頭都佔優

| k | 3×3×3 中位/p95 | 終態聚攏度均值 | 4×4×4 中位/p95 | 終態聚攏度均值 |
|---|---|---|---|---|
| 0（關閉） | 2.338s / 3.794s | 0.690 | 18.810s / 20.528s | 0.576（4/8 撞上限） |
| **8（默認）** | **0.776s / 1.845s** | **0.787** | **4.396s / 7.757s** | **0.606** |
| 16 | 0.846s / 1.438s | 0.769 | 5.317s / 10.319s | 0.578 |

k 不是越大越好：k=16 的 4×4×4 反而更慢、終態更低（多算的候選把預算吃在「看起來像但不算真改善」的動作上）。
落盤：`cubic_gather_bench_k0.json` / `_k16.json`。

### 7.2 5×5×5（4 seeds，塊數 125）

| k | 中位 / p95 | 終態聚攏度 | 失敗原因 |
|---|---|---|---|
| 0 | 20.650s / 20.999s | 0.522 | 4/4 timeout |
| **8** | **12.786s / 15.877s** | **0.526** | 4/4 no_improve（跑完） |
| 16 | 19.396s / 20.168s | 0.556 | 2/4 timeout |

5×5×5 每輪候選約 250 個，預篩剪掉 96%（24071/25015）；k=8 是唯一能在 20s 內**跑完整段**的配置。

### 7.3 patience：80 已足夠

| patience | 3×3×3 中位 / 終態 | 4×4×4 中位 / 終態 |
|---|---|---|
| 80 | 0.776s / 0.787 | 4.396s / 0.606 |
| 160 | 1.363s / 0.792 | 7.105s / 0.607 |

終態只多 0.005 / 0.001，時間漲 ~75%，維持默認 80。

### 7.4 等級（step）

| 局面 | 中位 / p95 | 終態聚攏度 | 起點→終點 |
|---|---|---|---|
| 3×3×3 step2 | 0.975s / 1.522s | 0.750 | +0.403 |
| 4×4×4 step2 | 6.026s / 9.379s | 0.619 | +0.287 |
| 4×4×4 step3 | 3.548s / 5.819s | 0.689 | +0.344 |

**坑**：`3×3×3 step=3` 是無效配置（`new_cubic_puzzle` 要求 step < max(m,n,d)，等於 3 時建局失敗、盤面仍是還原態），
基準裡會顯示「8/8 solved、0 步、0.002s」——這是假數據，不可當結果。跑 step 對照前先確認 step < max 邊長。

### 7.5 非立方 3×4×5（6 種軸排列真正參與）

| 等級 | 中位 / p95 | 終態聚攏度 | 起點→終點 |
|---|---|---|---|
| step1 | 7.288s / 8.550s | 0.596 | +0.254 |
| step2 | 9.960s / 14.341s | 0.592 | +0.238 |

同量級立方（4×4×4）只要 4.4s；非立方慢 ~1.65×，因為 `cubic_metrics` 要枚舉 6 種軸排列
（立方只有 1 種）。這塊目前沒有按形狀剪枝，是下一步可量、可選的優化點。
