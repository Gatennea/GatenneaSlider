## 十七、待定：多实例端口是「抢占式」还是「自动递增」（用户 2026-11-06：先想，别动手）

**事实（已实测，勿再重复调查）**：`http.server.HTTPServer.allow_reuse_address = 1`，
在 Windows 上等价于 `SO_REUSEADDR` ⇒ **同一端口第二次 bind 不报错**。这就是「双击就能多开」
的机制（不是专门写的兜底）；代价是同一端口上多个实例**谁接到连線不可依賴**，请求可能落到
旧进程、跑旧代码。验收新代码的现行做法：新开实例换端口（`--http-port 5051`），不重启用户实例。

**要定的两条路**：
1. **维持现状**：多开可用，但 API 端口不可预测；文档里写清「换端口验收」即可（已写入 `agents.md` §20）。
   → 代价：外部脚本在多开时打错进程；好处：零改动、脚本默认连 5050 的预期不变。
2. **端口自动递增**：启动时先 `connect` 探测占用（不能靠 bind 失败——`SO_REUSEADDR` 让 bind 成功），
   占用则 `+1` 直到成功，并把实际端口印在 `GATSLI_TOKEN` 附近、写进 `ext_state['port']`。
   → 代价：改了「默认 5050」的行为契约，`macro/test_macro_http.py` 等硬编码 5050 的脚本要跟着改；
   好处：多开的每个实例 API 唯一可达。

拍板后：删本节，按选定路线落到代码 + `docs/api/AI使用API注意事项.md`。
