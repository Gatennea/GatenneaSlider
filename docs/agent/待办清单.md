## 十七、待定：多实例端口是「抢占式」还是「自动递增」（用户 2026-11-06：先想，别动手）

**事实（已实测，勿再重复调查）**：`http.server.HTTPServer.allow_reuse_address = 1`，
在 Windows 上等价于 `SO_REUSEADDR` ⇒ **同一端口第二次 bind 不报错**。这就是「双击就能多开」
的机制（不是专门写的兜底）；代价是同一端口上多个实例**谁接到连線不可依賴**，请求可能落到
旧进程、跑旧代码。验收新代码的现行做法：新开实例换端口（`--http-port 5051`），不重启用户实例。

**要定的两条路**：
1. **维持现状**：多开可用，但 API 端口不可预测；文档里写清「换端口验收」即可（已写入 `agents.md` §20）。
   → 代价：外部脚本在多开时打错进程；好处：零改动、脚本默认连 5050 的预期不变。
2. **端口自动递增**：启动时先 `connect` 探测占用（不能靠 bind 失败——`SO_REUSEADDR` 让 bind 成功），
   占用则 `+1` 直到成功，并把实际端口印在 `GATSLI_TOKEN` 附近、写进 `ext_state['port']`。
   → 代价：改了「默认 5050」的行为契约，`macro/test_macro_http.py` 等硬编码 5050 的脚本要跟着改；
   好处：多开的每个实例 API 唯一可达。

拍板后：删本节，按选定路线落到代码 + `docs/api/AI使用API注意事项.md`。

## 六十、`_test_cubic_vk.py`「箭头互不重叠」判据误报（2026-11-19 主目录核实，豆包，已完成）

> **已完成 2026-11-19（豆包分支）**：判据已从 `pygame.Rect.colliderect`
> 改为 `_cubic_arrow_shapes` 实际正面多边形的 mask 相交；保留一条
> 「同一枚箭头和自己比必须相交」的检查，避免把断言放宽成永真。
> `test/_test_cubic_vk.py` 现 **52/52** 全绿；箭头的 AABB 角部重叠不再误报。
>
> **现象**：该测试 50 过 1 红，报「箭头互不重叠（4 处重叠）」。豆包分支单跑同样红，
> 不是合并冲突；main 合并 f773488 时按已知判据问题收下。
>
> **已核实的证据（主目录实测，2026-11-19）**：3×3×3、视角 0、选中切面 `r`、选块后
> 四枚箭头 c/C/d/D 的命中盒：
> - c (807,568,119×88)、C (990,568,119×88)、d (908,645,88×117)、D (920,461,88×117)；
> - 4 处包围盒相交只是斜角：c-d 18×11、c-D 6×10、C-d 6×11、C-D 18×10，面积 60–198 px²，
>   相对单枚命中盒（约 1 万 px²）占 1–2%；四个中心两两相距 85–98 px，主体不碰；
> - **按 `_cubic_arrow_shapes` 的实际多边形做 mask 相交，六对全部 None（0 处重叠）**。
>
> **根因**：箭头是世界空间斜薄板，投影后包围盒是轴对齐 `pygame.Rect`，斜薄板会把四个
> 空角框进去，正交两向的箭头在对角处必然相交。该判据写于「箭头钉在切面四边外沿」的
> 旧实现；豆包 c26030c 改成「四枚都锚在上一次点击处、各沿方向偏 0.22 格」后，包围盒
> 贴近是设计的自然结果，不是渲染回归。
>
> **做法**：把判据从 `rect.colliderect` 换掉——优先用 `_cubic_arrow_shapes` 的多边形
> 做 mask 相交（与上面实测同法）；退一步可改成「任一箭头中心不落入另一枚的 rect」。
> **别直接删断言或放宽成「允许重叠」**：真出现两枚压在一起时还得报红。
>
> **验收**：`test/_test_cubic_vk.py` 全绿，且保留一条能抓「两枚箭头真重合」的检查
> （中心距阈值或多边形相交）。
>
> **协作**：箭头是豆包改的（c26030c / 756048f），挂豆包；用户 2026-11-19 说豆包分支
> 暂不同步，等它下轮同步后按本节修。只 commit 到自己分支、不推送不合併。
