## 十一、待定：`engine` → `solver` 反向依赖（打乱死局防护）怎么解耦

- **为什么算问题**：engine 是最底层（GUI 与求解器都向下依赖它），它反过来

- **为什么不能简单搬**：`deadend_guard` 依赖 `solver.table_core.canonicalize`
  （平移归一 + D4 变体位打包的那套大方阵逻辑）。把 deadend_guard 搬进 engine

- **三条路（要定的就是这个）**：
  1. **钩子注入（倾向）**：engine 侧只留一个可选注册表（新

     `test/_test_shuffle_guard.py` 守住「4_4_2 打乱终态不在死局里」。
  2. **把 `canonicalize` 连同 `deadend_guard` 一起下沉到 engine**：分层最干净，
