## 六之二、捆绑谜题：为什么不做成第四个子菜单（2026-10-26 23:5x 定案）

用户原话：「三个子菜单不动，新增一个捆绑，捆绑谜题可以从原版四种派生，也可以从
模型谜题派生。」讨论后选的是**分组**而不是平行子菜单：

- 前三个子菜单的维度是**几何板型**，捆绑是**目标态的结构**，两者正交。并列会出现
  「4×4 + 粘连」与「4×4」分居两处、✓ 分两处显示，且每加一档要加两处。
- 自动派生还缺一条「粘法」规则：方形可以「每两块粘一起」，三角 / 米字 / 模型每族
  都要另定，且要逐档验「粘完还能不能动、打不打得乱」，不合格的档位只能缺着。
- 分组方案零新格式：条目仍是 `('名','__custom__','名')`，分组标题渲染分支现成。

**「从模型谜题派生」目前缺一步**：模型谜题进不了格子画布（`_is_model_kind` 拒绝），
所以现在只能从内置四形态派生。要让模型谜题也能当起点，得先决定「模型板型的捆绑
存在哪」（模型文件加可选 `groups` 字段 / sidecar / 样式文件声明 `kind=模型名`），
落盘位置定了才谈得上派生。**这是这条待办的真正剩余部分。**

**顺带修掉的既有洞**：带粘连的局原来能进竞速，但竞速初始局面只记「哪些格子有块」
（`export_map` 是 0/1 或 `#/_`），不记谁和谁粘着 → 成绩还原出的是另一道题。
现在 `mode_allowed('timed')` 见到任何 `group != 0` 就拒，并给一句人话原因
（与模型板型被拒是同一类问题：那边丢朝向，这边丢捆绑组）。
