## 三、待修 bug：自造謎題的**復原判定**失靈（用户 2026-10-26 23:10 报）

**用户原话**：

> 记录新发现的bug：自定义谜题的复原判定存在问题。
> 复现：导入最新的shield存档，最后一个快照是复原态，但是游戏内并未判定为复原

**状态：待查（未动手）。** 记的时候只做了两件事：确认这不是「没有复原通知」这类
纯 UI 问题（左下角状态也是「未复原」＝判定本身回了 false），并把判定链路读了一遍。

**判定链路（已读，供后续省事）**：`GUI.is_solved` → `EngineGame.is_solved`
（`engine/adapter.py:666`；模型板 `_goal_keys is None` → 走 `Board.is_solved`）→
`Board.is_solved`（`engine/board.py:573`）= `canonical_key() == spec.goal_canonical()`，
其中 `canonical_key` 在**晶格对称群**下取最小规范形（块键带朝向时，朝向标签也一起
被 `_orient_perm` 置换）。

**已排除的一条**：还原态本身不会自检失败——`engine/model_validate.py:247` 对每个模型
文件都验过「还原态 `is_solved()` 为真」，shield 也在其中。所以问题几乎必然在**还原出来
那一局与 `goal_blocks` 不逐键相等**：要么位置差、要么**朝向标签**差，要么 canonical
的对称变换把朝向标签置换错了（这条最可疑：手写模型的朝向表与晶格对称群不是同一个来源）。

**动手第一步**（别改判定，先拿证据）：载入用户那份存档的最后一个快照，把
`game.board.keys` 与 `spec.goal_blocks` 的 `(point, orient)` **逐键 diff**，看差在哪一维；
若两集合完全相同而 `is_solved()` 仍为假 → 直接锁定 `canonical_key` 的对称/朝向置换。

复现材料：`models/shield.json`（28 块）；存档在 `archives/`（自动存档）或玩家另存
的位置；用户手上有那份「最后一个快照是复原态」的存档。

## 四、待办：悬停缝隙时高亮那条缝（用户 2026-10-26 23:10 提）

> 「添加悬停在缝隙上的缝隙高亮，用处是在点击之前就知道这里是否可以点。」

即：鼠标悬停在可点的缝上（**可点**＝当前锚下这条缝真能切开），缝线先高亮；不可点
的缝维持灰。已有的相邻能力：缝隙命中判定带（`ae67527` / `196bad7` 修过两轮）、
`test/_check_gap_annot.py`（三形态一致性验收）、`test/_test_sq_seam_hint.py`。

⚠️ 三形态（square / tri / mi）+ 模型板型必须同时生效（`AGENTS.md §3` 铁律）。

## 五、待办：设计谜题时「自动朝向」判定过严，想选的方向选不到（用户 2026-10-26 23:10 提）

> 「设计谜题时对自动朝向的判定不够完善导致有时候不能选择想选的方向，但是该方向并不会导致不可玩。」

现象：搭积木里 R/F 转朝向时，某些朝向被挡，但那个朝向其实完全可玩。
待查：编辑器里「当前朝向」的候选集是怎么来的（`_med_rot_v` / `_med_mirror_v` +
吸附/连通/门禁），是不是把「保存门」的一部分（连通 + ≥2 可动）提前到了每次旋转
上，从而挡掉了中间态；也可能是同朝向共顶点那套 snap 逻辑把合法朝向误判。
**判据必须与「保存时才查门」一致**（见 `docs/spec/模型文件_2026-10-24.md` §8.6 附近）。
