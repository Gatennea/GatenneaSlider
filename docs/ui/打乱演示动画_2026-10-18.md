# 打乱演示动画（2026-10-18）

## 说人话（先看这段）

点「打乱」之后不再「啪」地一下换盘：先把棋盘**放回打乱前的样子**，把打乱过程**一步步重演**给你看。打乱步数太多时只演前 50 步（步长跟随速度滑动条，最快档 50ms/步 ≈ 2.5 秒），然后整屏淡出、在全遮住的瞬间切成打乱结果、再淡入——看到的就是「演示几步 → 转场 → 打乱结果」。

- **历史步数照旧清空**：打乱后从 0 开始计，演示只是「放映」，不记历史、不计步、不弹「复原」窗。这条语义与加动画前完全一致。
- **演示期间棋盘锁输入**（既有动画守卫自动生效）；演示正常结束或被打断（再次打乱 / 撤销 / 删成绩 / 换盘），棋盘都会对齐到打乱终态，绝不留在演示中途。
- 门控：enhanced 界面模式 + 滑动动画开关开着 + 本局打乱确实有可演步骤。任一不满足 → 与以前一样瞬时换盘。

## 需求原文（用户 2026-10-18）

> 添加打乱时动画，打乱结束后仍然要清空历史步数，不过当打乱步数过大时动画可以只演示前面的一些步骤，几秒后淡去再显现打乱结果。

> 调参反馈（同日）：打乱动画太慢，12 步太少 → 步数调到 50。
> 步长同步缩到 150ms/步：若仍按 300ms/步，50 步要 15 秒，反而坐实「太慢」。
> 当前节奏：50 步 × 150ms ≈ 7.5s + 淡出淡入 0.7s ≈ 全程 8.2s。

> 二次反馈（同日）：要速度滑动条最快的速度 → 本机 config 的
> `animation_speed` 设为 50（滑动条最快档，范围 50–1000ms）；演示步长改为
> **跟随滑动条当前值**（上限 150ms 截断）。最快档下 50 步 ≈ 2.5s，
> 全程 ≈ 3.2s；滑动条设置不被演示改写（播放期临时截断、收尾恢复）。

## 实现

### 1. 动作记录（game 层，三形态贯通）

- `game.py` 新增模块级 `record_shuffle_move(record, game, gap_type, line, direction, step, final_positions)`：把一步打乱翻译成与玩家滑动动画同构的记录 `{'moved': [...], 'final': [...]}`（`moved` = 该步涉及的块当前位置列表，可直接喂 `start_animation`）。
- `game.py` / `game_mi.py` / `game_triangle.py` 的 `shuffle` / `_shuffle_once` / `_random_move` 均增加 `record=None` 参数，在两个提交点记录；**死局重试时 `record.clear()`**（那轮的移动作废）。
- 三角的 `_random_move` 记录的是「一步单位移动」——1443 条那种量级，演示只取前 50 条，无性能顾虑。

### 2. 演示状态机（gui/animation.py，`_start_shuffle_demo` 一族）

- 常量：`SHUFFLE_DEMO_STEPS = 50`、`SHUFFLE_DEMO_STEP_MAX_MS = 150`（演示步长**跟随速度滑动条当前值**、上限截断 150ms：滑动条最慢档 1000ms 时 50 步要 50 秒，必须截断；最快档 50ms 时演示按 50ms/步连播 ≈2.5s）、`SHUFFLE_FADE_MS = 350`（淡出/淡入各 350ms，合计 ~0.7s「几秒后淡去」）。
- 步长保护：播放期 `animation_duration` 临时截断，`_start_shuffle_demo` 存原值（`_shuffle_demo_prev_duration`）、`_clear_demo_state`（所有收尾路径的公共出口）恢复——**滑动条设置不被演示改写**。
- 状态机：`play`（逐条重演）→ `fade_out`（蒙层渐满）→ 全遮瞬间把棋盘切成打乱终态 + 视图适配 → `fade_in` → `_finish_shuffle_demo`（补发「已打乱」通知）。
- **复用玩家滑动管道**：`start_animation` / `commit_animation`，三形态（方形/三角/米字）的渲染插值自动生效，零形态分支。
- `commit_animation` 演示分支：`_reset_anim_state()` 后直接推下一条记录——**不记历史、不计步、不弹复原窗**（历史早在 `shuffle_puzzle` 里按终态重置）。
- `cancel_animation` 演示中止钩子 `_abort_shuffle_demo`：先把棋盘对齐终态再清动画态（否则常规取消路径会把块拖回动画起点，抵掉终态对齐）。
- **游戏对象身份锚** `_shuffle_demo_game`：所有换盘路径都是 `self.game = create_puzzle(...)`（换对象）。锚失效（reset / 新局 / 载入 / 成绩回放）→ `_shuffle_demo_stale()` → 只清状态、绝不往新棋盘写旧位置。

### 3. 逻辑态 vs 视觉态（关键设计，别绕晕）

演示期间 `game.blocks` 的 location **视觉上**是打乱前状态（重演需要），但**逻辑上**盘面早已是打乱终态。因此所有「盘面语义查询」演示期必须按终态回答：

- `_demo_logic_positions()` 上下文管理器（animation.py）：演示期临时把 blocks 换成终态、`matrix` 缓存进出还原，退出后外部无感；嵌套安全（depth 透传）；锚失效不修正。
- 消费者：`GUI.is_solved`（拆出 `_is_solved_positions` 核心）、`gui/events.py:_get_game_status`（blocks / matrix / solved / solver_state / 米字 q·lat、三角 up 全部走 with 块）。
- **踩过的坑**：`_test_numbered_timer` 抓出「打乱后仍判胜」——演示期 `is_solved()` 看到打乱前（复原态）盘面返回 True，违反既有语义。修法就是上面的上下文管理器，不是关掉动画。

### 3.5 重大 bug：淡出转场后 `animating` 卡死（2026-10-18 当晚修复）

**症状**：打乱之后不能滑动、快捷键全部失效（撤销/重做/自动求解除外——它们在守卫豁免清单里）。

**根因**：截断演示的淡出阶段会手动 `animating = True` 挡输入（`_play_next_shuffle_record`），但淡入结束的 `_finish_shuffle_demo` → `_clear_demo_state` **从没把它复位**。此时 `anim_blocks` 已空，`commit_animation` 第一行 `if not self.anim_blocks: return` 直接返回——标志永远卡 `True`，`events.py` 的 KEYDOWN 守卫（420 行）与拖拽守卫把所有输入吞掉。`_shuffle_demo_active` 已置 False，所以「演示收尾」类断言抓不到，测试盲区。

**触发条件**：打乱记录数 > `SHUFFLE_DEMO_STEPS`（走淡出路径）。该 bug 自功能第一版（12 步）即存在，非调参引入；调成 50 步后需 >50 步才触发。

**修法**（`_clear_demo_state`，所有收尾路径的公共出口）：`animating` 且 `anim_blocks` 为空 → 复位。后者保证不误杀正在播的真实动画（如换盘后新局的过渡）。

**回归测试**（`_test_shuffle_demo.py`）：T3/T4 收尾后断言 `animating` 复位；另加端到端穿透探针——F2（指标面板，不在守卫豁免清单）post 进事件队列走 `handle_events()`，面板应翻转。animating 卡死时该键被吞、面板不翻，即用户体感的「快捷键失效」。

### 4. 渲染与视图

- `gui/renderer.py` 新增 `draw_shuffle_fade()`：全屏 `SRCALPHA` 黑蒙层，`GUI.py` 主循环接线（与 `_update_shuffle_demo()` 成对）。
- `gui/session.py` 抽出 `_fit_board_view()`：三角按打乱后包围盒重适配 zoom + 居中，其余 `ensure_blocks_visible()`；演示切终态的瞬间也调它（藏在蒙层后）。

## 顺带修复：pytest 显式文件参数双跑（test/conftest.py）

`pytest test/_test_mi_http.py`（显式文件参数）时，pytest 的 isinitpath 跳过 `python_files` 检查，内置 Module 收集仍把脚本型测试 **import 整跑一遍**（起 HTTP server、构造 GUI、发完全部请求），与 ScriptTestItem 的子进程双跑并抢端口——子进程的请求被父进程 import 版的 server 吃掉，10s 超时假红（`_test_mi_http` / `_test_http_api` 实证，旧代码同样中招，非本次回归）。

修法：`_NoImportModule`（不 import 的 Module 替身，`collect()` 返回空）+ `pytest_pycollect_makemodule`（tryfirst）对 `_test_*.py` 抢先返回替身，从源头拦住；`pytest_collection_modifyitems` 去重保留兜底。修复后 `_test_mi_http` 从 23s 假红变 11s 真绿。
