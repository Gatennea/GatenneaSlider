# 搜索改进设计（命令面板 / 帮助框 / 大模型兜底）

> 作者：貓九  ·  状态：规划完成，Phase 1 已落地  ·  2026-10-15

## 1. 目标

让玩家「想用的功能找得到」。本项目的痛点是**功能可发现性**——玩家
「能找到的不一定会用，想用的不一定找得到」。游戏内两套检索入口共用一份
结构化清单 `gui/feature_index.py`：

- **命令面板**（Ctrl+K，`gui/palette.py`）——键盘优先，只做检索与跳转。
- **帮助框**（`gui/dialogs.py` 顶部搜索框）——文档为主、检索为辅。

两入口都调同一个 `_fi.search()`，因此**只改检索内核、两处一起升级**是铁律，
绝不各自抄一份。

**最终形态**：结构化检索（精确/别名/包含/模糊）覆盖绝大多数口语查询；
当结构化检索拿不准（零命中 / 低置信）时，由**大模型 AI 兜底**把自然语言
意图映射到功能，或给出真人级解释。

## 2. 现状（已读代码确认）

- `feature_index.py`：43 条功能，`_haystack` / `_score` / `search`。
  语义：按空白分词 + 每词必须命中（AND）+ 子串打分；返回 `(score, entry, available)`。
- 两个入口都调 `_fi.search()`（palette.py:89、dialogs.py:687），改内核两处受益。
- 已确认痛点：
  1. **中文无空格失配**：「三角求解」「撤销步」被当成一个 token，别名里没有整串 → 0 命中。
  2. **疑问前缀失配**：「怎么撤销」「能不能着色」的「怎么/能不能」成了必须命中的词 → 0 命中。
  3. **同分靠插入序**：两个都 60 分就按清单顺序排，无相关性精排。
  4. **空查询不列项**：打开面板空查询只给占位符，错失「浏览发现」机会。
  5. **零命中只说「换个说法」**：无相近推荐。
  6. **结果无分类 / 无快捷键**：扫一眼分不清类型、不知键盘能否直达。
  7. **无拼音检索**：打拼音找不到（着色 / zhaose）。

## 3. 设计原则

- **单一真源**：检索内核只在 `feature_index.py`，UI 两处同步受益，不各自抄。
- **返回形状稳定**：`search()` 维持 `(score, entry, available)` 三元组，避免牵连 UI。
- **加性新函数**：`list_all()` / `suggest()` 为新增，不动旧签名。
- **纯函数、易测**：检索逻辑不依赖 pygame，单测可直接 `import` 跑。
- **不引入拼音库依赖**：拼音走人工别名（零依赖、可控、不膨包）。
- **AI 兜底为可选项**：无 API key / 离线时优雅降级，绝不阻断现有检索。

## Phase 1 — 检索质量（地基，已落地 ✅）

**S1 中文无空格也能搜**
新增 `_fuzzy_score`：整串（无空格组合词）与「名称+别名」各 token 算最长公共
子序列（LCS），重叠 ≥2 字才给分，上限 50（低于别名包含 60，精确/包含仍优先）。
→「三角求解」与「聚拢求解 / 异形谜题预设档(三角)」共享「求解 / 三角」(2 字) 即命中。
主路（分词 AND）全失时才走模糊兜底，不影响既有精确匹配。

**S2 疑问前缀剥离**
匹配前剔掉疑问外壳：`怎么/如何/怎样/咋/在哪/哪里/为什么/能不能/能否/是否/
可以吗/我想/我要/请问` 等前缀，及句尾语气词 `吗/呢/呀/啊/吧`。
→「怎么撤销」→「撤销」直接命中；「能不能着色吗」→「着色」。

**S3 同分精排**
多词命中越多给小加成；二级排序键 = (可用, 综合分, 强命中数)，其中强命中 =
名称/别名命中（≥60）。同分不再靠清单插入序，相关性优先。

> 实现位置：`gui/feature_index.py` 的 `_strip_question` / `_lcs_len` / `_fuzzy_score`
> 及重写后的 `search()`。返回形状不变。

## Phase 2 — 空 / 零查询体验（补「可发现性」短板）

**S4 空查询列全部** `list_all(form, mode)`
`query` 为空时返回全部 43 条（带可用性），按 `(available, 分类优先级, 名称)` 排。
命令面板 / 帮助框打开即变「功能地图」，逛也能发现功能——正治本。

**S5 无结果推荐** `suggest(query, form, mode, k=3)`
非空但 0 命中时，用 LCS / 编辑距离挑最相近 2–3 条，显示
「你是不是想找：…」。代替干巴巴的「换个说法试试」。

**UI 接线**：`palette.py` 与 `dialogs.py` 两处都要接——空查询走 `list_all`、
零命中走 `suggest` 渲染。

## Phase 3 — 呈现 + 拼音

**S6 分类标签 + 快捷键芯片**
给 feature 数据加可选 `shortcut` 字段
（undo→Ctrl+Z、palette→Ctrl+K、virtual_keyboard→F1、metrics→F2、
records→F3、redo→Ctrl+X、shuffle→Alt+S、reset→Ctrl+R …）。
每条结果加小分类 tag（动作 / 开关 / 概念 / 面板 / 建局 / 链接）+ 快捷键芯片，
两入口同步。

> 顺手修一致性：`dialogs.py` 用 `▶/✕` 而 `palette.py` 因游戏字体缺字形刻意回避
> （改颜色）——统一处理，避免豆腐块。

**S7 拼音检索**
不装库，改在 `aliases` 人工补拼音（着色→`zhaose`/`zs`、撤销→`chexiao`/`cx`、
求解→`qiujie`…）；`search` 已对 aliases 做包含匹配，拼音自然生效。

## Phase 4 — 大模型 AI 兜底（最终目标）

### 动机
结构化检索（含 S1–S3 模糊）能覆盖绝大多数口语，但长尾自然语言——
「我想把棋盘退回刚才那一步」「这局卡住了怎么搞」——仍可能零命中。
此时由大模型把**自然语言意图**映射到功能清单，或给出真人级解释。

### 架构（可选项，离线降级）
1. **检索先跑**：UI 零命中 / 低置信时，调用 `gui/feature_ai.resolve(query, form, mode)`。
2. **后端选择**（不绑死）：
   - 桌面版（pygame exe）：直接调 LLM HTTP API（需用户在设置里填 API key /
     自建代理）。无 key 时**跳过**，回到 S5「想找…」推荐，绝不崩。
   - 未来若加官网/服务端：可把兜底放服务端，但当前仓库官网纯静态、无服务端，
     主入口必须在游戏内（既有结论），故优先桌面端直连方案。
3. **Prompt 设计**：把 `FEATURES` 的 (name, aliases, howto, 当前可用性) 作为
   上下文，要求模型**只返回功能 id 列表或一个简短自然语言答复**，不编造功能。
4. **安全边界**：模型返回不在 `FEATURES` 的 id 一律丢弃；给出答复时标注
   「AI 建议，仅供参考」。
5. **扩展点**：`feature_index.search` / `suggest` 已返回结构化结果，AI 只作为
   「最后一道兜底」，不替换既有检索。

### 本阶段交付物（部分已落地 ✅）
- ✅ `gui/feature_ai.py`：`resolve()` 接口 + OpenAI 兼容 LLM 调用 + **离线降级**（无配置即返回 []）。
  启用：`GATENNEA_AI_ENDPOINT` / `GATENNEA_AI_KEY` / `GATENNEA_AI_MODEL` 三个环境变量。
- ✅ `palette.py` / `dialogs.py`：零命中路径已接 AI 兜底（search → suggest → AI），
  未配置时静默退回 suggest，**绝不阻断现有检索**。
- ⏳ **设置页 UI（TODO）**：AI 兜底开关 + endpoint/key 输入框（替代改环境变量），尚未做。
- ⏳ **可点击直达**：帮助框里 AI 建议目前为只读文本（命令面板侧结果可点击）；
  帮助框 AI 建议的点击激活留待设置 UI 阶段一并做。

## 风险与已规避

- LCS 计算量极小（45 条 × 短串，O(n·m) 可忽略），零性能顾虑。
- 模糊只在「名称+别名」token 上算 LCS，且重叠≥2 才给分，已验证
  `search('zzzz不存在的东西')` 仍返回 `[]`（无垃圾误中）。
- IME：前缀剥离只作用于已提交文本，不影响组字途中状态（`TEXTINPUT` 已处理）。
- 拼音走人工别名，不增依赖、不膨包。
- 严守「单一真源」，不破坏现有「可用性排序 / 位置无关」断言。
