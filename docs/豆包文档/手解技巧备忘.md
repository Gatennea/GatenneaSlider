## 1. HTTP 通道
- base `http://127.0.0.1:5050`；头 `Authorization: Bearer <token>`（进程重启令牌失效需重新索取）
- 写操作序列：`POST /select_gap {type:"h"|"v", line:N}` → `POST /select_block {row,col}` → `POST /move {direction:"w"|"s"|"a"|"d"}`
- 只读：`GET /map`、`/status`（含 blocks 绝对坐标）、`/analysis/actions`（合法动作枚举，不含块明细）
- **撤销/重做存在**：`POST /undo`、`POST /redo`（无参数）→ 可大胆试错后回退
- 每步后 sleep 700–800ms 等动画结束；`animating=true` 期间勿连发
- 工具回显偶发被吞 → 一律 `curl.exe -s ... -o "$env:TEMP\x.json"` 再读文件
- `select_gap` 失败时 selected_gap 不变，先 GET /status 核对再继续

## 2. 已实测规则
- **连通性**：移动后所有块必须整体连通；组内只要有一块连着主体，即可把相邻组块一起拖走（"悬空必断"顾虑过严，S12 实证）
- **缝隙归属（精确，5×5 局实证）**：
  - h 缝 `line=L`：above 侧 = row ≤ L，below 侧 = row > L（line 行属于 above！）
  - v 缝 `line=C`：left 侧 = col ≤ C，right 侧 = col > C（line 列属于 left！）
  - 之前"line 行不属于任何侧"是误判（被连通组件现象误导）
- **移动方向绑定（关键！v+a 组合被拒）**：v 缝只能 w/s（上下），h 缝只能 a/d（左右）；用错方向服务端直接拒"当前缝隙不允许 X 方向移动"
- **连通组件规则（重要）**：缝隙移动只带动**选中块在该侧的连通组件**（BFS），不是整侧所有块；选中不同块移动范围不同 → 拆组件、逐块搬运靠选对"种子块"
- **多米诺连锁**：组件移动时若目标位被组员占据，连锁推挤直到空位（不是整组同步平移）；链尾必须有空位
- **全局连通检查**：移动后任意滑块脱离主体即拒"移动后滑块会断开"；被拒时先 GET /status 核对 blocks 坐标再换动作
- **左边界**：可向右推到 col0；但满 4 行的组再整行右移会被边界拒绝（S15 被拒）
- **上边界**：row -20 允许（S20 实测）——整列上移不必再怕越界，这是收官破局的钥匙
- **h 缝 line 归属**：块恰好在 line 所在行时归属可能不符预期（R4 在 row -15 时，h line=-15 失败、line=-16 成功）；失败就换相邻 line
- **timed 模式禁 /solve**；切 practice 会重置局面（无提示）——别用切换来保存残局

## 2.5 5×5 双锚结构经验（2026-10-15 实测）
- **双 5 连锚**（两行各 5 连）达成后，中间缺口难补：锚行两端（c2/c6）及 c4 列都是"锚列"，竖向操作必拆锚；横向 h 缝操作带整侧组件
- **r-6 型夹死**：单块被上下两块夹住时（如 c6 列 6 连），上下都撞、左右组件巨大 → 只能靠拆锚或长程重组解开
- **收官方向**：先定目标窗（如 rows r-8..r-4 × cols c2-c6），数清窗外块数与窗内缺口数必须相等（对账），再逐块搬运；补给被锚行挡住时，宁可拆一个锚重组，不要硬顶

## 3. 收官模板：单块电梯死锁 → 列瀑布
**死锁**：底部单块要上移，正上方必须空（缺口）；正上方空则它悬空断连，正上方有块则顶不上去 → 单块永远进不了满行上方。
**破法（列瀑布接力，实测 5 步）**：
1. `v` 缝整列下移 ×2：把缺口从上层逐行"传"到目标行（每步只动一列，副作用可控）
2. 底部块用 h 缝左/右移，借"满行桥"滑到缺口列正下方
3. `v` 缝整列上移一格：底部块升入缺口、上方缺位被同列顶替 → 一次换位补两格
- 关键：缺口不必在目标块正上方硬顶，而是**让缺口移动来接住块**（缺口会走，块不会飞）

## 4. 竞速心态
- 卡住时优先用 undo/redo 做有底试错，不要纯脑内推演十几轮
- 用 /analysis/actions 枚举合法动作，被拒动作不盲重试
- 相对地图与绝对坐标两套心智模型切换时，用 blocks 坐标交叉校验
